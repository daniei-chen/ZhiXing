# 知行 0.20.0 · 每条回答都有「详情」

## 问题

气泡里只有正文和失败句。想知道这一轮花了多久、调了几次工具、有没有子任务、出来几个文件、有没有占位符没还原、失败时是哪个错误码——这些信息分散在工具时间线、执行面板和气泡下面那行灰字里，用户得自己拼。

0.17.0 的边界里写着「导出/分享/请求详情没有同样的标记」。导出与分享在 0.19.0 补上了，剩下这块就是「在回答旁边能一次看清这一轮发生了什么」。

## 怎么改

新增纯函数模块 `src/run-summary.js`：

- `durationText(startedAt, finishedAt)`：先看毫秒，不足 1 秒给「不到 1 秒」，再按秒/分秒展示；任一端缺失就返回空串，绝不把运行中的 `updatedAt` 当结束时间。
- `runSummary(message)`：状态（已完成／未完成／已取消／进行中）、耗时、工具记录条数、子任务数、产出数、无法归属的占位符处数与说明、错误码。
- `summaryRows(message)`：把它排成「标签－值」行，没有产出/没有还原问题/没有错误码时不生成空行。

界面：助手气泡里在错误句上方加一个 `<details className="run-summary"><summary>详情</summary>`，展开显示这些行。助手消息在发送时记 `startedAt`，在收尾时由 `finalizeConversationRun` 补 `finishedAt`（取终态事件时间）。

单测 6 条钉住：不足 1 秒不四舍五入成 1 秒、缺端点不出耗时、失败/取消文案、运行中不算耗时、还原处数进详情、没有产出时不显示空行。

## 边界

- 详情的耗时取自消息上的 `startedAt` 与终态事件时间；**旧消息没有 `startedAt`**，会显示「未记录」，不回填。
- 工具调用数是轨迹里工具事件条数（调用与结果各算一条），不等于「工具种类数」，也不代表这些工具都成功了。
- 详情不显示本次请求的脱敏内容；请求原文仍在审阅弹窗里看。这条边界要留着：请求文本不写进工作区存储。
- 「原文还原」行只在有无法归属的占位符时出现；正常一轮不会显示，避免让人以为总有问题。
- 错误码显示的是主进程记录的 `errorDetail.code`（如 `HTTP_401`），不是给用户看的整句文案；整句文案仍在气泡里。
- 安装生命周期本版未重跑；`ENOTFOUND` 文案仍未端到端触发；安装器未签名；`visualAcceptance`、`crossWindowsUserDecryption` 仍 `outside_scope`；真实子任务归档仍未通过。
