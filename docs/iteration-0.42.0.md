# 0.42.0 · 工作面板标签与右侧交付预览

## 目标与范围

本轮从已发布 0.41.0 的文档归档提交 `cabb754b08883902b12f876e2d68338a7699d5fb` 继续 Phase 1。目标是让工作面板的真实功能可发现，并在查看交付文件时继续编辑聊天。Electron、React、Harness 和生产依赖版本不变。

核对依据为锁文件对应的四个官方 Harness `0.2.2-rc.5` 包源码。交付卡片及行内引用在上游进入右侧资源预览，查看器有加载、失败、重试及请求代次控制。源文件位置和 SHA256 见 [机制核对](workbench-preview-0.42.0.md) 与 [上游证据](evidence/0.42.0/upstream-workbench.json)。本轮未读取用户本机 Harness 安装或重新打开其桌面窗口；对标结论保持“部分”。

## 用户可见改动

- 工作面板原来的下拉选择器改为带图标和文字的横向标签。浏览器、文件、终端、侧边聊天、执行、改动、产出、统计、详情九个视图保留原功能。窄面板可横向滚动；左右方向键循环选择，Home/End 到首尾，只有当前标签进入 Tab 焦点顺序。
- 点击交付卡片、已解析的行内文件引用或产出列表，在右侧「产出」页显示本机提取文字。聊天输入仍可用；显式点击「放大预览」才打开原文档弹窗。
- 预览提供加载、原位错误、重试及返回列表。保留读取范围和警告，显示前 12,000 个 JavaScript 字符单位，超过时明确标注；无提取文字时说明限制。文件正文作为文本显示，不执行 HTML 或外部资源。
- 切换聊天、项目、项目目录或视图作用域，关闭面板和返回列表会使旧预览结果失效。连续选择文件只接收当前请求的结果；同一面板内切换其他标签可保留本次临时预览。

## 安全和状态边界

仍经 `listDeliverables` 取得本会话交付记录，再以主机签发的 `id` 调用 `readDeliverable`。路径只能用于选择已返回的记录，不能单独授权读取。HMAC、会话归属、私密文件排除、文件身份复验、大小和解析超时限制均沿用原主机实现。

正文仅在预览 Hook 的临时状态中，不写入消息、资料、草稿或工作空间，不自动发送给模型。列表返回后也校验请求代次，关闭或切换后不会再启动过期的正文读取。已进入主机的解析 IPC 仍可能运行至完成或原超时，本轮只丢弃迟到结果，没有新增取消协议。

## 工程和发布

新增真实 React renderer 的预览竞态和标签键盘回归，并将 Windows 实包 `test:workbench-preview` 接入 PR 打包和正式发行的必需门禁。专项以临时项目、真实 Harness `write/present` 和本地合成模型服务完成交付，检查真实文件、预览、键盘、会话隔离、窄屏及深色，留存截图和包身份。

原有八份工作面板相关 UI 脚本迁移到新标签结构，原业务断言保留。发布装配和证据收集同步包含 `workbench` 结果；失败、取消、跳过或缺失都不能发布。针对 0.41.0 已观测到的“创建 draft 成功后立即查询为空”，只对查询缺失作四次有界重试，校验真实 ID、tag、源码提交和 draft/prerelease 状态，不重复创建或吞掉 API 错误。

首次 Windows 候选的工作面板专项为 9/10，窄屏换行文件引用被测试驱动误判遮挡。生产组件的实际几何复现证明整体矩形中心不在文字片段内；驱动改从可命中片段选坐标，保留真实遮挡拒绝和原生鼠标事件，并增加真实 Electron/CDP 回归。产品布局没有为通过测试而改变；失败原件和复现见 [候选验收调查](evidence/0.42.0/candidate-validation.md)。

**正式验收发现的草稿原子替换边界：** 首次 main 发布运行 `45935856822` 在 Phase 1 的草稿文件替换中收到真实 `EPERM`，最终读取因保存未完成而拒绝；专项为 2 通过、1 失败，后续 4 项未执行。具体文件占用者未知，正常退出时重存成功不抵消该失败。资产装配和发布已被门禁阻止，修正须通过新 main 构建的 Windows 验收后才能发行；没有以 PR 候选通过或重试读取替代。原字节日志、结果、截图及其余门禁计数见 [首次正式验收记录](evidence/0.42.0/release-attempt-1/README.md)。

修正复用 `harness/privacy-bridge.mjs` 既有的 Windows `EPERM/EACCES/EBUSY` 原子替换重试，将它作为 `renameEncryptedTemp` 供串行工作空间／草稿保存使用。重试只提交同一个已写好的密文临时文件，不重新加密、重新生成数据或先删旧目标；八次等待合计 1100 ms，另有文件系统调用耗时。持续失败仍交由保存队列保留错误及待存快照。其他凭据、保险库和反馈写入方式未扩展。新增真实 Windows 无删除共享权限句柄的占用回归，以及保存队列的原子替换与显式恢复回归；原有 Phase 1 的阈值、读盘核对及失败行为保持不变。

源码说明不预填 Windows 通过数。该次构建的实际提交、测试计数、包内指纹、启动测量、安装器 SHA256 和发布状态，以发行资产 `acceptance-summary-0.42.0.json`、`windows-acceptance-0.42.0.md`、`packed-source-manifest.json` 和上传核验收据为准。

## 本轮没验证什么

- 固定九个功能标签仍非 Harness 的完整动态资源 Dock、多文件标签、浮窗和布局恢复；右侧是提取文字，非原版 Office/PDF/图片查看器或文档编辑器。
- Linux 聚焦组曾得到 50 项中 46 通过、3 失败、1 跳过。三项在未修改基线独立复现：目录链接清理的 `ENOTDIR`、缺少 `powershell.exe`，以及既有 `/tmp` 路径脱敏覆盖缺口。最后一项不是凭证泄漏，也不能全部归为环境失败。记录见 [基线复现](evidence/0.42.0/linux-baseline-failures.json)。不因此降低 Windows 门禁。
- 本地组件夹具和截图不替代全应用浏览器、Windows 实包、全部 DPI 或真人视觉验收。专项的本地合成模型服务不代表真实云端办公成功率。
- 没有运行安装器、用户安装升级/卸载恢复、自动更新生命周期、跨账户 DPAPI 或代码签名；没有触碰 `D:\应用\知行`、读取其凭据或清理其历史产物。
- 没有完成内联审批、Thinking、富文本扩展、排队纠偏、完整 App 拆分、Resident Host、SQLite、Git 快照或专业 Office 引擎，不宣称整个 Phase 1 完成。
