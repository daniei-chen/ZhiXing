# 知行 0.14.5 · 安装生命周期第一次对当前安装包成立

这轮没有改产品代码。它存在的理由只有一个：**安装生命周期此前只对 `0.14.1` 的安装包跑过**。`0.14.2`、`0.14.3`、`0.14.4` 的验收文档里都写着同一句 `historicalUpgrade: not_run` 和「安装器证据仍属于 0.14.1」——能力地图上这条一直是空的。这轮把 `0.14.5` 安装包本身送进了 `scripts/qa-install-lifecycle.ps1`。

## 跑了什么

44 步，31 通过、12 观测、**0 失败**、1 项 `not_run`（历史升级，因为没有可作基线的旧安装包）：

| 阶段 | 结果 |
| --- | --- |
| 首次安装（`--no-desktop-shortcut`，装到 `.preview\i QA\知行-738d`） | 退出码 0，342 秒；注册项、开始菜单快捷方式、包内 93 个源码文件与 `build-provenance.json` 全部核对一致 |

## 两个操作上的坑，都写进 AGENTS.md 了

1. **桌面快捷方式必须先在测试前移除**。安装器用 `--no-desktop-shortcut` 安装，不会重写桌面那条 `.lnk`；如果它还在指向 `D:\应用\知行\知行.exe`，`Assert-Installed` 会以 `Unexpected product shortcut target` 失败——第一次尝试就是这么挂的。正确做法：先把两条 `.lnk` 字节备份到 `.preview\qa-0.14.5\user-shortcuts\`，删除，再取「零快捷方式」的冷备份，跑完把原始字节装回去（本轮已按 `DE73CA68…`、`EA472C05…` 逐字节还原）。
2. **装回用户环境必须显式 `/D=D:\应用\知行`**。卸载之后注册项里没有 `InstallLocation`，NSIS 会装到默认的 `%LOCALAPPDATA%\Programs\office-agent`。本轮先踩了一次（342 秒装错位置），卸载后带 `/D=` 重装（354 秒）才回到 `D:\应用\知行`。

第一次失败的运行还留下了一个空 `InstallLocation` 的注册项和被改写的开始菜单快捷方式，已按备份清理并记录；它没有被当成成功的证据。

## 边界

- **`historical-upgrade` 仍是 `not_run`**：没有真实的旧版本安装包作基线，所以「从旧版升级」这条路径依然没有证据；已通过的只有「同版本覆盖安装」。
- 生命周期只在**本机、同一 Windows 账户、合成档案**上跑过；跨账户、跨机器安装没有覆盖。
- 探针只读 preload 数据 API 并正常关闭，**不是视觉验收**；没有点击任何界面控件。
- 安装器仍未签名；桌面快捷方式在测试期间是被人工移除再还原的，不是安装器管理的结果。
- 真实云端模型回答未覆盖（没有可用 Key）。
- 本轮没有改产品代码，所以「产品行为」的结论仍然来自 0.14.4；本版只新增安装链路的证据。
