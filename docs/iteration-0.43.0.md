# 0.43.0 · 交办可批准、可取消、可恢复

## 目标与范围

从 0.42.0 继续成熟化，先补齐人机协作的执行闭环：实际工具申请批准时，在所属聊天输入区显示明确操作；用户允许、拒绝、停止或重新载入后，主机与界面的结果一致。本轮不更换 Electron、React、Harness 或生产依赖。

用户再次要求“真正成熟、适配 Harness 全部能力且具有自己的特色”。本轮沿用官方底层协议，把中文办公任务的操作对象、命令、联网范围、覆盖风险和交付结果放在可检查的位置。机制与差距见 [原生核对与生命周期说明](approval-recovery-0.43.0.md)。

## 产品改动

- 普通工具审批由 Windows 模态弹窗改为所属聊天输入区的审批卡，只提供“仅允许本次 / 拒绝”，保留停止任务。可切换聊天；其他聊天的请求有独立待处理入口。命令和范围完整显示，多个请求逐项决定，不批量授权。
- 必要提问与方案审批沿用原生协议，改为按根会话保留、可重新读取的输入区交互。输入框暂时接管时草稿与附件保持挂载，语音和浮层暂停，不令整个应用 inert。
- 新原生审批桥透传实际取消信号，过期/重复/跨任务答案不能授权；Harness 仍负责原生策略与审计。自动化不继承人工批准。
- 启动前保存原消息定位；刷新后接回原运行的完整私有结果，保存确认前不释放交接记录。不会为了重连再跑一遍模型或工具。
- 全局界面恢复明确停止当前交办并保存；初始保存尚未完成时也会预取消，避免旧页面继续启动。正常退出同样拒绝晚起任务；保存重试成功后确认结果交接，读取重试使用相同的运行接回路径。工作面板单独恢复仍只重建面板。
- 关闭本地保存的任务在真正重载/renderer 崩溃时撤销；不把临时正文偷偷写入持久库。未确认退出的隔离继续保留，确认后再收口。

## 工程验证与发行

新增 broker、原生 Cordis/HTTP、真实 Harness 文件副作用、私有结果交接、问题恢复与 renderer 交互回归。实际受控负例曾暴露错误恢复互等、初始保存后晚起任务、结果回调失联及卸载信号差异，均以相关回归约束修复。

Windows `test:approvals` 接入 PR 目录包与正式发行必需门禁，检查允许/拒绝/停止的文件副作用、同 callId 独立请求、切聊天、刷新后原 runId 的完整结果、正常退出、全局恢复及不保存模式重载取消。源码、组件、Sites、包内测试和既有专项继续执行，门禁失败不发布。源码说明不预填尚未运行的 Windows 通过数；发行资产由该次实际日志自动装配。本机分组运行、实际失败负例与修复后日志见 [源码层证据](evidence/0.43.0/local/summary.json)，不将这些独立分组相加为完整套件总数。

## 本轮没验证什么

- 普通工具审批卡不是原生 Action Cards；会话/永久放行、Auto Reviewer 和 OAuth 未做。
- 委派子 Agent 原生 approval policy 固定为 never，需要新增审批的操作会被拒绝；没有改成可弹审批或自动允许。
- 结果交接只覆盖同一个存活主机与既有消息定位，不是跨主进程崩溃恢复、常驻内核或任务队列。
- 本地完整 Electron 试跑被单实例 Unix socket EPERM 阻断；没有用组件通过替代全应用或 Windows 实包结论。
- 真实云端、用户安装/升级/卸载恢复、跨账户解密、签名与完整 200 包桌面视觉未覆盖，未接触用户 D 盘安装。
- Resident Host、SQLite、Git 快照、专业 Office 引擎、项目 RAG/记忆仍需各自里程碑，不能称本轮完成全部成熟化。
