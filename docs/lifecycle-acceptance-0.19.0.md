# 知行 0.19.0 安装生命周期复跑

本轮不改产品代码：在 0.19.0 已发布安装包上重跑完整安装生命周期，并带上 0.14.0 历史基线的升级路径。

## 做了什么

1. 关停应用，逐字节备份两条快捷方式后删除，取冷备份（`backup-host-bytes.ps1`）。
2. 卸载用户安装（`Uninstall 知行.exe /S /currentuser --keep-shortcuts`，退出码 0，安装目录已清空）。
3. 装 0.14.0 到 `D:\qa-baseline-0140`（300 秒，退出码 0），用**基线自己**建立三项目合成档案（`sourceAppVersion=0.14.0`），再卸载基线并清掉它留下的快捷方式。
4. 带 `-BaselineInstaller release\ZhiXing-0.14.0-x64.exe` 跑 `qa-install-lifecycle.ps1 -Mode Run`。
5. 装回 0.19.0（309 秒，退出码 0），按字节还原两条快捷方式，启动确认 4 个进程。

## `%TEMP%` 残留复查（P1 顺带）

- 安装前后 `%TEMP%` 里 `ns*.tmp` 目录数：安装前 12 个 → 装回后 11 个；**今天这两轮安装（0.19.0 装两次、0.14.0 装两次）没有新增目录**，NSIS 正常退出会清掉自己的插件目录。
- 剩余 11 个目录里**没有任何一个包含带「知行／`zhixing` 标记的可执行文件**，按产品规则（0.14.6／0.14.13）它们无法被证明是知行留下的，因此清理逻辑保持不动——这是有意的保守，不是漏清。
- 其中 `nsZZQ2.tmp` 里有一个 `payload.exe`，但不含知行标记；不下结论说它是谁的。

## 边界

- 口径仍是**同账户合成档案**：无真实凭据、无启用中的自动化；跨账户解密、逐像素界面没有覆盖。
- 合成档案来自 0.13.2 模板项目，只验证结构迁移与哈希稳定，不代表真实用户历史数据。
- 只验了 0.14.0 → 0.19.0 一条升级路径；0.15.x、0.16.x、0.17.x、0.18.x 的中间版本升级没有单独跑。
- `%TEMP%` 只做了读数与归属扫描，没有清理那 11 个无法归属的目录（不猜、不误删）。
- 安装器仍未签名；本轮没有新版本、没有新 tag。
