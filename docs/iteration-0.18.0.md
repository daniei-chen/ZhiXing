# 知行 0.18.0 · 供应商页选思考强度，错误文案端到端复验

## 做了什么

### 1. 供应商页里能选思考强度

之前档位只能在输入框浮层里选，选模型在供应商页、选强度要跳到输入区。现在供应商页的模型列表下面多了一块「当前模型的思考强度」：

- 只列出**当前模型真实支持**的档位（内核四档 off/low/high/max 的子集），当前档位有实心描边；
- 点了就写回同一个工作区设置 `settings.reasoning`，与输入框浮层完全同源；
- 三种情况给明确解释，而不是静默失效：模型不是当前模型、档位未确认（需要刷新目录）、已保存的档位不受该模型支持。

判定逻辑抽成纯函数 `src/provider-reasoning.js`（`currentModel` / `reasoningChoices` / `reasoningState`），6 个单测钉住档位来源、顺序、缺档位与不受支持的提示。

实现时踩到一个真问题：`provider.models` 是保存的原始记录，里面**没有** `levels`；档位只出现在运行时扁平的 `runtime.models` 里。第一版读错了地方，界面一直说「档位尚未确认」。修法是先从 `runtime.models` 找，找不到才退回原始记录，并补了一条「扁平清单缺失时不崩」的用例。

### 2. P0-1 错误文案端到端复验（挂了两版）

`npm run test:errors` 在 0.18.0 实包上跑通：真实 401（`api.deepseek.com` + 假 Key）、真实连接被拒（关闭的端口）、真实 12 秒超时、以及不存在的主机名，四条都显示可行动文案，且与主进程日志里的技术原文不同；主进程日志保留真实错误码（HTTP 401 / ECONNRESET / ECONNREFUSED / TIMEOUT）。

**一个必须说清的偏差**：这次「不存在的域名」在本机网络下返回的是 `ECONNRESET`，不是 `ENOTFOUND`，所以 `ENOTFOUND` 那条文案（`解析不到服务地址…`）**仍然没有在实包上端到端跑过**，只是映射表里有。脚本按真实错误码选择期望文案，因此它仍然是一条有效的端到端证据，但不能记成「DNS 失败已验证」。

## 边界

- 供应商页只改**当前模型**的档位；不能给目录里每个模型各记一份偏好。换模型后要重新确认档位（输入框浮层的行为一致）。
- `ENOTFOUND` 文案仍未端到端验证（本机网络把它变成 ECONNRESET）。
- 档位是否真的影响模型行为，本版没有做对照实验；只验证了设置写入与界面状态。
- 启动探测这一轮没有采到首次内容绘制（`rendererFirstContentfulPaintMs: null`），不是 0，也不能当作退化或改善。
- 安装生命周期沿用 0.17.0 的完整证据（53 步 / 38 通过，0.14.0 → 0.17.0），本版未重跑；两版差异只在设置页的渲染层，但这一点不能替代重跑。
- 安装器未签名；`visualAcceptance`、`crossWindowsUserDecryption` 仍 `outside_scope`；真实子任务归档仍未通过。
