# 知行 0.12.2 · 能力状态与恢复边界

本轮从已发布的 `v0.12.1` 继续，内核仍固定 DeepSeek Harness `0.2.2-rc.5`。本轮先处理上一版明确保留的 R09、R10、连续新草稿恢复和能力状态误报，再把新增回归纳入源码与包内测试入口。Windows 安装包的最终文件、校验值和安装生命周期以 [0.12.2 Windows 验收记录](windows-acceptance-0.12.2.md) 为准。

## 本轮修改

- **R09 锁恢复**。加密隐私桥的主锁和 guard 在创建目录后、写入 owner 前发生进程终止时可以恢复。活进程 token 继续保持独占，死 owner 才能回收。异常 owner、失效 PID、目录或文件链接、并发替换和 Windows 删除中状态均采用失败关闭策略。回收不会递归删除未知路径，也不会重复执行更新回调。
- **R10 目录分页**。`office_list_files` 保留原调用方式并增加 `offset` 与 `limit`。结果包括 `total_entries`、`next_offset` 和 `truncated`。直接条目按原始 UTF-16 文件名排序，单次最多扫描 10,000 项，超限明确报错，不返回不完整清单。每页重新扫描，目录变化时要求从第一页重新检查。
- **多份新草稿**。连续创建的未发送草稿拥有独立可见入口，可逐份切回并保留附件和原归属。首次发送时草稿绑定实际聊天，发送失败在原地恢复正文和附件。删除项目或聊天后，迟到的附件解析结果不能复活已删除草稿。
- **能力状态清单**。设置中的 Agent 内核页读取真实注册工具和模型实际看到的工具声明，分别显示 `registered`、`effective`、`enabled` 和 `blockedReason`。PTC 显示为模型直达的 `run_code`，经程序调用的办公工具显示为程序化调用。项目目录、完全访问、协议、联网授权、规划模式和浏览器/自动化桥接都会影响当前状态。
- **回归入口**。新增能力清单、R09、R10 和草稿 native/UI 测试，并将相关测试加入 `npm test`、`test:components` 和 `test:packed`，避免只在临时命令中验证。

## 已验证结果

源码回归执行 `npm test`，结果为 **335 项，334 通过，0 失败，0 取消，1 条件跳过**，耗时约 225.28 秒。跳过项是 Windows 不授予文件符号链接权限时的 `owner.json` 符号链接测试。真实 junction 和注入式 owner-symlink 元数据测试已执行通过。

组件与 Windows Electron 隔离旅程执行 `npm run test:components`，结果为 **14/14**。其中包括能力设置页的迟到结果隔离、三份新草稿的真实 DOM 回切、JSON 文件重载、首次发送失败后的聊天归属和删除项目后的迟到附件保护。该层使用隔离 profile 与合成 IPC，不读取用户资料，也不代表最终安装包。

前端 `npm run build` 通过，Sites `npm run test:sites` 为 **4/4**。源码测试中的模型、MCP、脱敏、Office、语音、PTC 和文件边界使用本机合成收件服务或本机进程。真实云端供应商、真实凭据和用户业务资料未纳入本轮。

## 能力和隐私边界

普通交办继续自动脱敏，不增加每次发送的重复确认。规则、字段、校验位、自定义词、已配置凭据和当前策略仍由现有隐私链路处理。R09 保护的是隐私映射文件的并发和崩溃恢复。它不等同于通用 DLP、全面 NER、任意编码识别或视觉打码。

当前清单可以说明某项能力是否注册、是否满足本次路由和权限条件，以及它是否通过 `run_code` 间接调用。它不能把工具目录、配置开关或一次目录检查升级为真实云端质量、长期稳定性或完整上游功能验收。

常驻 Harness Host、跨启动 live jobs/MCP、MCP 和供应商 OAuth、独立搜索连接、Responses/Gemini、异构子模型路由、完整原生文件和 Agent Office 工具、模型视觉、原图打码、全面 NER、增量加密事件/Blob 存储、typed XLSX 和正式 DOCX 模板仍未全部接入。

工作区全量加密写回和 12 MiB 上限保持不变。持续不可写时，强杀或断电前尚未落盘的自动化结果仍不能保证恢复。PTC 继续默认关闭，并且只有绑定项目、完全访问和相应内核开关同时满足时才可执行。
