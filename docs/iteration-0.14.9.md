# 知行 0.14.9 · 一次交办的多个子任务合成一份归档

## 问题

0.14.8 让每个子任务的对话可以单独归档。一次交办如果委派了三个子任务，用户得点三次「归档」、拿三个文件，还得自己拼起来给别人看。

## 怎么改

执行面板「协作子任务」标题行多了「全部归档」：把这次交办里所有**有对话**的子任务合成一份 Markdown，逐个子任务一节，没有对话的子任务跳过。

- 排版仍是纯函数：`archiveAllMarkdown` 复用 `archiveMarkdown`，把每节的标题降一级（`##` 子会话、`###` 子消息），顶部写明子任务数量、所属会话与归档时间。
- 只有一个带对话的子任务时不出这个按钮，避免和单条「归档」重复。
- 写盘还是走主进程 `subagent:archive`（同一个 2 MB 上限、同一个取消语义），文件名默认 `子会话-全部.md`。

## 结果

| 层 | 结果 |
| --- | --- |
| 源码 | `npm test` 395 个：394 通过、1 跳过、0 失败（归档单测从 4 个增到 6 个） |
| 实包 | `npm run test:archive` 5 项全过：单条归档、批量归档（两个子任务合成一份、标题降级、第二段内容在文件里）、取消不写盘 |
| 回归 | 打包源码 347、组件 14、站点 4、原生文件 5、错误文案 4、聊天失败 2、更新缓存 3、临时目录 2、ZIP 4，全部通过 |

## 边界

- 批量归档只覆盖**当前选中那次交办**的子任务；跨交办、跨会话、定时归档都没有。
- 仍然只归档对话文本：工具参数、原始返回、产物文件不在文件里。
- 归档文本是界面显示（已脱敏、可能截断）的版本，不是内核原始会话。
- **真实子任务归档仍未跑通**。本轮新增了实包脚本 `npm run test:subagent`（本地假模型服务让主会话调用 `subagent`，子会话应自己再发一次模型请求），实际结果是：主会话成功发起子任务（工具返回 `started subagent qa-sales`，profile 里也确实生成了子会话历史文件），但**子会话没有向配置的供应商发出任何模型请求**，等待 30 秒仍然没有。怀疑是子会话没有继承当前供应商路由（退回内置 DeepSeek，于是请求打到了别处），本轮未查实、未修复。这个脚本不进发布门禁，`0.14.9` 的归档实包验收仍然是脚本注入的合成子会话记录。
- 只在 Windows x64 实包验证；安装生命周期未复跑，`historical-upgrade` 仍 `not_run`；安装器未签名；真实云端未覆盖。
