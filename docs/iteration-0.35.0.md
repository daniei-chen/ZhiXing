# 知行 0.35.0 · 窗口装不下时，别再让人去查 API Key

## 解决什么问题

0.34.0 让上下文窗口跟着型号走以后，切换型号的失败会走到桌面版同一条路径 `MODEL_SWITCH_COMPACTION_FAILED`。但那一轮验收里看到一句很刺眼的话：内核明明说的是「压缩没能把这段历史变小」，界面给的却是——

> 模型未完成本次请求。请检查服务地址、模型 ID、API Key 或额度。

地址、模型 ID、Key、额度，这四样没有一样能解决「历史装不下小窗口」。用户会照着这句话去换 Key、去查余额，全都白折腾。真实失败码只躺在日志里，界面上一个字都没有。

## 怎么改

两处，各一层，缺一不可：

1. **主进程把失败码带进句子**：`electron/run-failure.mjs` 的 `HINTED_CODES` 加上 `MODEL_SWITCH_COMPACTION_FAILED`。这张表是白名单，只有能指向下一步的代码才进；不加这一行，渲染层根本收不到代码。
2. **渲染层换成窗口的说法**：`src/error-copy.js` 增加一条映射——

   > 换到的新模型装不下这段对话历史，压缩也没能腾出空间。请改用上下文更大的模型，或新建聊天后继续。

   这条不是「网络故障」类，所以放在 `CONTEXT_WINDOW_EXCEEDED` 旁边，措辞按知行的口吻，给出两条真正的出路。

## 结果

- 源码层（单测）：`tests/error-copy.test.mjs` 8/8。新增两条断言——`failureHint` 对这条代码返回该码且 `turnFailureMessage` 的句子里带中文括号，`friendlyError` 把整句换成窗口文案；同时钉住「目标代码以外的码不臆造提示」（`CONTENT_REFUSED` 仍返回空串）。
- Windows 实包层：`npm run test:model-window` **4/4**。第 3 例从「显示未完成」升级为两条硬断言：正文必须含「装不下这段对话历史」，且**不得**再出现「检查服务地址、模型 ID、API Key 或额度」。这条断言是在真实内核抛出的那次失败上跑的，不是合成字符串。
- 同一实包上 `test:overflow-recovery`、`test:compact-command` 复跑通过，压缩链路的其它口径未受影响。

## 边界

- 只改了这一条失败码的文案。`IMAGE_OFFLOAD_REQUIRED` 等未触达过的代码仍没有专属文案，落回通用句——因为它们**没有被实验触发过**，编一句文案就是猜测。
- 界面文案确实换了，但**没做视觉核对**（字号、换行、窄窗口下是否溢出），只有文本断言。
- 切换压缩的**成功路径仍未验证**：0.34.0 那轮的合成摘要（3 个字）被「摘要须小于原文」拒绝，本轮没有再攻这条；它仍是待办，不是已完成。
- 真实厂商没有参与：失败码来自桌面版在同一台机器上真实抛出的异常，供应商是本地假服务。
- 窗口上限的可信区间、Anthropic 字段写法等 0.34.0 的边界原样保留。
