# 知行 0.15.2 · 真实云端下的文件工具（工作区会话）

## 问题

0.15.1 只证明了「本地假服务 + 真实内核」能出工具时间线。真实云端那一层一直空着：我先用真实供应商在**首页会话**里让模型调用 `glob`，模型明确回答「本次会话没有 glob 工具」。查 `electron/runtime.mjs` 才确认：文件工具按 `workspaceRoot` 挂载，首页会话没有工作区，所以根本没有这些工具。这不是模型撒谎，是产品结构决定的。

## 怎么改

没有改产品代码，补的是**验收能力**：`scripts/test-real-cloud-workspace-tools.mjs`（`npm run test:workspace-tools`）

1. 在一次性临时 profile 里建一个临时工作区目录，放两份 `.md` 和一份 `.txt`；
2. 通过 `loadWorkspace`/`saveWorkspace` 注入项目与工作区（`directory` 指向该目录），并把当前工作区切过去；
3. 重新加载界面，**点进项目**（首页会话没有文件工具，这一步是关键），确认输入框存在；
4. 用真实供应商发一句「请调用 glob 工具，列出当前工作区根目录下所有 .md 文件」；
5. 断言：消息下方出现工具时间线、出现文件类工具调用、回答里带回数量 2。

## 边界

- **只验了 `glob` 与目录列举两类文件工具**，没有验写入、覆盖、`apply_patch`，也没有验文件工具之外的终端、MCP。
- **没有验脱敏在工具结果路径上的表现**：这一轮工作区里只放了不含敏感信息的 md，工具结果回到模型时是否按策略掩码、界面是否还原，仍未覆盖。
- 工作区是脚本注入的（`loadWorkspace`/`saveWorkspace`），不是用户从「新建项目」对话框一步步选的；界面路径本身在 0.14.x 有过验收，本版没有重跑。
- 首页会话没有文件工具是**既定的产品结构**（工具按工作区挂载），不是缺陷；但用户如果期望在首页直接读文件，会得到「没有这个工具」的答复。
- 安装生命周期本轮未重跑；真实子任务归档仍未通过；安装器未签名；`visualAcceptance`、`crossWindowsUserDecryption` 仍 `outside_scope`。
