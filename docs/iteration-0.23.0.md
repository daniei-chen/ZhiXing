# 知行 0.23.0 · 压缩事件第一次在实包上真的发生

## 问题

0.22.0 把压缩阈值对齐了桌面版（headroom 8,192 → 65,536，128k 窗口下阈值 54,272），但那一版只能说「按公式算出来是 54,272」。压缩到底会不会在实包里触发、触发之后请求会不会变小、界面有没有留下痕迹——一条都没验过。0.22.1 又修了 `image-offload` 的虚报，压缩这一侧更需要一次真实运行把结论钉住。

## 怎么验

新增 `scripts/test-compaction-ui.mjs`（`npm run test:compaction`），在 Windows 实包上跑本地假 OpenAI 服务：

1. 注入供应商与设置（脱敏模式、完全访问），刷新页面。
2. 每轮发一句「第 N 轮：请复述上文并继续。」，服务返回约 6,750 tokens 的填充文本（`'上下文填充：知行压缩验收。'.repeat(2400)`）。
3. 服务把每次请求的原始字符数、消息条数、是否摘要请求、是否带检查点全部记进证据。
4. 判据不是猜的，取自 `dsh-compaction-basic/lib/index.js`：
   - 摘要请求：最后一条 user 消息以 `You are now acting as a compaction engine` 开头（`COMPACTION_INSTRUCTION`）；
   - 压缩后的请求：正文含 `This is an automatically generated checkpoint`（`CHECKPOINT_PREAMBLE`）。
5. 断言排在 `record()` 之前——第一版把 `record()` 写在断言前，16 轮根本没触发压缩却报了两条 PASS，当场改掉。

## 结果（实包 0.22.1 上跑出，本版复跑一致）

| 轮次 | 请求字符数 | 消息数 | 摘要请求 | 带检查点 |
| --- | --- | --- | --- | --- |
| 1 | 28,274 | 5 | 否 | 否 |
| 6 | 184,759 | 15 | 否 | 否 |
| 7 | 216,056 | 17 | 否 | 否 |
| 8 | 155,332 | 14 | **是** | 否 |
| 9 | 122,222 | 10 | 否 | **是** |

- 第 7 轮 216,056 字符 ≈ 54,000 tokens，正好顶到 128k 窗口下的 54,272 阈值；第 8 轮先发摘要请求，第 9 轮就带上了检查点前言，请求从 216,056 掉到 122,222 字符（省 93,834 字符，约 23,000 tokens），消息数 17→10。
- 界面：压缩后 8 条助手消息仍在页面上，`.run-error-detail` 为空，详情行（状态／发送方式／耗时）正常。
- **界面没有压缩提示**，这是刻意的：`dsh-client-ui-trajectory/lib/client.js`（370 KB）与会话包里都搜不到 `compacted`／`checkpoint` 的前端渲染，`dsh-compaction-basic/locale/zh.json` 只有 meta 标题。桌面版不提示，知行也不加。测试里把这条写成断言（`desktopHasNotice:false`），哪天要加提示，得先证明桌面版加了。

## 怎么改产品

没有改运行时代码。这一版加的是**验收能力**：`npm run test:compaction` 进入日常门禁，压缩从「公式结论」变成「实包可复现事件」。AGENTS.md 记下了做法、判据字符串来源与两个写测试的教训。

## 边界

- 只验了「压缩会发生、请求会变小、界面不报错」。**没有评估摘要质量**——模型换成真实云端后摘要是否保住了该保的信息，未验。
- 只用本地假服务，不是真实云端；真实云端下这个长度会花真钱，也没验过。
- `image-offload` 的真实卸载仍未观察（0.22.1 起只是启用）。
- 小窗口 headroom 收缩分支仍只有单测。
- 安装生命周期仍是 0.19.0 的 53 步证据；`ENOTFOUND` 文案仍未端到端触发；安装器未签名。
