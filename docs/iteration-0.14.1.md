# 知行 0.14.1 · 错误文案第一次真正端到端跑通

这条待办欠了两版。0.13.9 加了友好文案，0.14.0 把它接进五个界面，但两版都只验证了「映射函数本身」，没有一次真实故障走到界面上——因为**真实故障根本走不到映射**。

## 发现

用一个打包 EXE 走真实供应商设置（假 Key、不存在的域名）才看见：`electron/model-catalog.mjs` 的 `fetchModels` 把所有 `fetch` 失败都 `catch` 掉，重抛一句固定的话：

```js
} catch { throw new Error('无法读取模型列表，请检查网络和 API 地址。'); }
```

于是 `ENOTFOUND`、`ECONNREFUSED`、`ECONNRESET`、12 秒超时，到界面时全变成同一句话，`src/error-copy.js` 里那些 `ENOTFOUND`／`ECONNRESET` 模式永远匹配不到。

只有 401 是「碰巧」生效的：HTTP 状态被拼进了 `读取模型列表失败（HTTP 401）`，而映射表里正好有 `/401/`。**这就是漏洞能藏两个版本的原因**——最常被提到的那个用例是好的。

## 改了什么

`electron/model-catalog.mjs` 新增 `failureCode(error)`：从 `error.cause.code`、`error.code` 或 `TimeoutError` 里取一个受格式约束的系统错误码（`^[A-Z][A-Z0-9_]{2,40}$`），拼进消息：

- 连不上 → `无法读取模型列表（ECONNREFUSED），请检查网络和 API 地址。`
- 域名失败 → `…（ECONNRESET / ENOTFOUND）…`
- 超时 → `…（TIMEOUT）…`

界面侧不改：`src/error-copy.js` 仍然是唯一的映射点，把带错误码的整句换成可行动文案。原始技术句留在主进程日志与诊断里，不进界面。取不到合法错误码时不编造号码，保留原来那句兜底。

## 验证到哪一层

| 层 | 证据 |
| --- | --- |
| 源码 | `tests/error-copy.test.mjs` 5 项：11 条映射、IPC 包装剥离、非 Error 入参、未匹配保持原样、真实关闭端口；（已并入 `npm test`，369 项） |
| 合成运行 | 本轮没有合成服务层：故障全部用真实网络与真实本机端口制造 |
| Windows 实包 | `scripts/test-error-copy-ui.mjs` 对 `release/win-unpacked/知行.exe`（0.14.1）驱动真实设置页：真实 401（`api.deepseek.com`）、不存在的域名、关闭端口、挂起服务 12 秒超时；四处界面文案逐条断言，并把主进程日志里的四条技术句与界面句配对，断言两者不同；应用退出码 0 |
| 真实云端 | 只覆盖「真实服务端拒绝」这一条路径：`api.deepseek.com/models` 返回真实 401。**没有**有效 Key，因此真实模型回答仍未覆盖 |

实包实测显示的四句话：

| 故障 | 界面 |
| --- | --- |
| 真实 401 | API Key 无效或已过期，请在「设置 · 供应商」中更新后重试。 |
| 不存在的域名（本机表现为 ECONNRESET） | 连接被中途断开，请检查网络后重试。 |
| 关闭的本机端口 | 服务地址拒绝连接，请确认地址和端口是否正确。 |
| 无响应服务 12 秒 | 请求超时，请检查网络后重试。 |

## 边界

- **`ENOTFOUND` 在本机不可复现**。这台机器的 DNS 把任何域名解析到 `198.18.0.x`（透明代理/TUN），连过去被重置，真实错误码是 `ECONNRESET`。所以「解析不到服务地址」这句只有源码层证据（`tests/error-copy.test.mjs` 的模式匹配），没有本机实包证据。
- **聊天发送失败时的界面没有测**。本轮只覆盖「设置 · 供应商」这一个入口；模型请求 401 落在会话正文里的显示是另一条链路（`运行未完成：…`），下一轮再验。
- HTTPS 证书错误、403、429 只有源码映射证据，未构造真实服务端。
- 真实模型回答、签名、真实云端质量仍未覆盖。
- 构建提交为 `3e0b5f1`；其后 `b3758ed` 只改测试脚本、本轮其余提交只改文档，都没有进入打包产物（`packed-source-manifest.json` 逐文件比对可复核）。
