# 知行 0.17.0 · 一处无法还原的占位符，不再毁掉整段回答

## 问题

0.16.0 的脱敏验收里撞出一个真实体验问题：只要模型**原样复述**一个不属于本次任务的占位符（比如它从别处学来的 `⟦ZX-…⟧` 记号），输出还原那一步就会整段抛错，气泡里只剩「输出包含无法归属本任务的占位符，已停止还原。」——用户失去的是一整段已经生成好的回答，代价和风险完全不对等。

那条保护本身是对的：跨任务的占位符绝不能在本次会话里被还原，否则可能把 A 任务的敏感值贴到 B 任务。问题在于「拒绝还原」被实现成了「拒绝交付」。

## 怎么改

`electron/runtime.mjs` 的还原段：

- 不再抛错；把 `restored.unknown.length` 记成 `unrestored`；
- 无法归属的令牌保持不还原，按原有规则统一显示为 `【敏感值待核实】`；
- 只要有无法归属的令牌，就用 `console.error` 记一行 `privacy.restore-unknown {"count":N}`（不含任何内容）；
- `result` 里带上 `unrestored`，界面在气泡下方显示一条灰色提示：`有 N 处占位符无法归属本次任务，已按【敏感值待核实】保留；原文没有还原，模型也没有看到原始内容。`

界面侧新增纯函数 `src/privacy-warning.js`（`restoreNotice`，3 个单测：0/负数不提示、带处数与标记、标记本身不是可还原令牌），`src/App.jsx` 在错误提示之前渲染它。

审计用例同步改写：原来那条「未知占位符必须让整轮失败」的断言，拆成「输出含凭证仍然失败」与「无法归属的占位符保留正文、不还原、记下处数」两条——后者明确断言结果里没有原始令牌、正文含 `【敏感值待核实】`、`unrestored === 1`、终态不是 failed。

## 边界

- **降级后的正文里，令牌位置显示的是 `【敏感值待核实】`，不是原文**；用户看到的是「这里有一处我没敢还原」。没人核对处数是否正确对应模型实际复述的次数，只按令牌数统计。
- 这条提示只出现在单条回答下方；会话导出、分享与「查看发送详情」里没有专门的标记，仍按普通文本处理。
- 只改了「无法归属」这一种情况；「占位符被模型改写、拼错」仍按未知处理，不会尝试模糊匹配。
- 假服务是本地 SSE，不代表真实供应商的复述习惯；真实云端那四套里没有一条故意让模型复述令牌（0.16.0 那次失败正是真实云端复现的，本版用同一机制在本地稳定复现并验证）。
- 安装生命周期本轮未重跑；真实子任务归档仍未通过；安装器未签名；`visualAcceptance`、`crossWindowsUserDecryption` 仍 `outside_scope`。
