# 知行 0.14.8 · 子会话归档：把一次子任务的对话留成文件

## 问题

知行跑原生子任务时，子会话的对话只能在执行面板里当场看。交办结束、换到下一条会话，那份「子任务为什么这么判断」的过程就只剩主会话里的一句结论。用户要留档、要给别人复核、要拿它当下一轮的输入，都没有出口。

## 怎么改

执行面板的「协作子任务」里，已结束且带有对话的子任务多了一个「归档」按钮：

1. 界面把这次子会话的对话（就是「查看对话」里显示的那几段，已是脱敏后的文本）排成 Markdown；
2. 主进程弹出原生保存对话框，默认落在当前项目工作区，默认文件名 `子会话-N.md`；
3. 写盘后在面板顶部提示「已归档到 路径」；取消保存不写文件、也不提示成功。

排版逻辑放在纯函数 `src/subagent-archive.js`：标题带子任务编号，元信息包含所属会话、状态、起止时间、消息条数、归档时间；被截断的消息标注「原始内容过长，归档里是界面显示的部分」，空消息写占位符，而不是留一个空标题。

写盘在主进程 `subagent:archive`：拒绝空内容、超过 2 MB 的文本；文件名过滤 Windows 非法字符并强制 `.md`；工作区不存在时退回系统默认目录。为了归档标题能写出会话名，会话标题从 App 经 Workbench 传入执行面板。

## 结果

| 层 | 结果 |
| --- | --- |
| 源码 | `npm test` 393 个：392 通过、1 跳过、0 失败（新增 4 个：标题与元信息、截断标注、拒绝空归档、空消息占位） |
| 实包 | `npm run test:archive` 4 项全过：子任务行出现「归档」入口 → 真实点击 → 原生对话框写盘 → 读回内容核对 → 取消不写盘 |
| 回归 | 打包源码 345、组件 14、站点 4、原生文件 5、错误文案 4+4、聊天失败 2+2、更新缓存 3、临时目录 2、ZIP 4，全部通过 |

实包证据里归档文件的开头是 `# 子会话归档 · 子任务 1`，元信息写着「所属会话：子会话归档验收」「消息：2 条」，正文两段分别是交办输入与子任务回答的原文。

## 边界

- 只归档**子会话对话本身**：工具调用的完整参数、工具原始返回、产物文件都不在归档里，归档不等于完整执行轨迹。
- 归档的是界面显示文本（已脱敏、已截断），不是内核里的原始会话；需要原始内容要另走导出链路。
- 只能归档**当前已选中那次交办**里的子任务；跨会话、批量归档、自动定时归档都没有。
- 不写入项目资料库，只落到用户选择的文件位置；没有版本、没有去重。
- 只在 Windows x64 实包验证；实包验收用的是合成子会话记录（由测试通过 `saveWorkspace` 写入），不是真实跑完一次模型子任务后点的归档——这一点必须在审计里读清楚。
- 合成 `trace` 事件结构会因字段缺失让渲染层整页空白，这是验收脚本造数据的坑，产品真实运行不受影响；脚本最终只注入了 `children`。
- 安装生命周期未在本轮复跑，`historical-upgrade` 仍是 `not_run`；安装器未签名；真实云端未覆盖。
