# 0.44.0 `@` 文件引用：机制、口径与边界

2026-11-27。本轮把审计第 8 项落地：**项目会话里输入 `@` 打开当前工作区的文件候选，插入的是相对路径文本**。
依据是仓库锁定的上游源码 `@deepseek-ai/dsh-file-reference@0.2.2-rc.5`、`dsh-file-reference-local@0.2.2-rc.5`、
`dsh-client-ui-input-trigger@0.2.2-rc.5` 与 `dsh-client-ui-reference@0.2.2-rc.5`；**没有重新取得用户 Windows 桌面窗口**，
所以涉及「桌面版现在长什么样」的判断一律是源码口径，不是窗口核对。

## 上游怎么做（源码依据）

| 位置                                                          | 行为                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `dsh-file-reference/src/grammar.ts` 的 `activeAtToken`        | 只认行首、空白或标点后的 `@`；`@"…"` 是带空格的引号形式；邮箱里的 `@` 不触发                                                                                                                                                                                                                                                   |
| 同文件 `formatFileMention`                                    | 插入 `@path`；路径含空白时用 `@"path"`；目录带尾斜杠，引号形式的目录保留未闭合引号以便继续下钻                                                                                                                                                                                                                                 |
| `dsh-file-reference/src/index.ts` 的 `FILE_REFERENCE_PROMPT`  | 明确告诉模型：`@` 是用户显式引用的路径，相对路径从工作区根解析，**内容要自己用 read 工具读，不许声称读过**                                                                                                                                                                                                                     |
| `dsh-file-reference-local/src/search.ts`                      | 索引只放路径；排序是「同名 1000 ＞ 文件名前缀 900 ＞ 文件名包含 700 ＞ 路径包含 500 ＞ 子序列 300+」、目录 +25，平分时目录在前、再按路径长度、再按字典序；默认 `maxResults 20`、`maxEntries 50000`；查询带 `/` 时改为列该目录的直接子项；默认排除 `.git`、`node_modules`、`dist`、`build` 等生成目录；点路径在显式打点前不出现 |
| `dsh-client-ui-input-trigger` 的 `detectTrigger`／`arbitrate` | `@` 与 `/` 共用一套候选菜单：上下键移动、Enter 选中、Esc（及 Shift+Tab）只关闭不选中、IME 组合期间所有键都放行                                                                                                                                                                                                                 |
| `dsh-client-ui-reference/src/client/index.ts`                 | 候选行是路径；目录行有两层动作（选中＝引用该目录，Tab／面包屑＝继续下钻）；文件与目录在正文里渲染成行内引用胶囊                                                                                                                                                                                                                |

## 知行怎么做

| 层         | 落点                                                                                                                                                                                                                                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 记号语法   | `src/file-mentions.js` 的 `activeMention`／`formatMention`：逐条移植上面的 `activeAtToken`／`formatFileMention`，含引号、邮箱排除与控制符拒绝                                                                                                                                                                                      |
| 输入正文   | `applyMention`：只替换当前记号，行尾补一个空格，其它 `@` 原文不动；没有活跃记号时不改写草稿                                                                                                                                                                                                                                        |
| 候选索引   | `electron/file-references.mjs` 的 `listReferenceFiles`：递归列出工作区，只给相对 POSIX 路径；私密清单**直接复用同一份 `isPrivateRelative`**（`.env*`、`*.pem`、`*.key`、`*.pfx`、`deepseek.credential`、`vaults`、`.git`、`node_modules` 与内部存储文件），符号链接不跟随、名字含 `:` 的条目不列，条目上限 50,000 并标 `truncated` |
| 主机桥     | `electron/main.cjs` 的 `workspace:list-references` → `electron/preload.cjs` 的 `listWorkspaceReferences`，作用域仍由 `workScope(options)` 决定                                                                                                                                                                                     |
| 筛选与排序 | `src/file-mentions.js` 的 `mentionState`：照上面的评分口径筛选、排序、截断到 20 条；查询带 `/` 时只列该目录直接子项；点路径在显式打点前不出现                                                                                                                                                                                      |
| 界面       | `src/Composer.jsx` 的 `@` 候选菜单：上下键移动、Enter（或 Tab）插入、Esc 关闭且不改草稿、输入法组合期间不抢键、切聊天关闭并重新取索引；一次 `@` 只向主机要一次索引，之后的按键只在本地筛选                                                                                                                                         |

插入的永远是**相对路径文本**：不加附件、不读文件内容、不把正文塞进上下文。模型要读内容仍然走原有的文件工具，
所以权限档位、文件审批与脱敏链路一律不变，本轮没有新增任何授权通道。

## 四档口径

| 项目                                                    | 档位                 | 依据                                                                                                                                                           |
| ------------------------------------------------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@` 记号语法（含引号、邮箱排除、目录尾斜杠）            | **已对标**           | 与 `grammar.ts` 逐条一致，`tests/file-mentions.test.mjs` 钉住                                                                                                  |
| 文件候选的筛选、排序、评分、20 条上限、目录内查询       | **已对标**           | 评分常量与并列规则照 `search.ts`，`tests/file-mentions.test.mjs` 钉住                                                                                          |
| 输入区键盘与 Esc／IME 行为                              | **已对标**           | 与 `dsh-client-ui-input-trigger` 的 `arbitrate` 一致，`tests/file-mention-ui.test.mjs` 钉住                                                                    |
| 候选发现放在主机侧、带失效与后台重建的索引              | **部分**             | 知行是「一次 `@` 取一份索引、渲染层筛选」，没有上游那套 `invalidate()` 与后台重建；工作区文件在本轮交办中被改动时，需要重打 `@` 才会看到                       |
| 默认排除生成目录（`dist`／`build`／`out`／`coverage`…） | **部分（有意偏差）** | 知行只按 `isPrivateRelative` 过滤：`build` 这类目录在本仓库同时承载源码，整体隐藏会让 `@build/…` 无法引用。条目上限承担同样的预算保护                          |
| `@` 对话／子代理候选                                    | **未做**             | 本轮只做文件；上游 `@` 同时列会话与子代理                                                                                                                      |
| 文件与文件夹行内引用胶囊、点击打开                      | **未做**             | 正文里仍是纯文本；上游把 `@path` 渲染成胶囊并接到右侧资源视图                                                                                                  |
| 目录行的下钻（Tab／面包屑）                             | **部分**             | 知行在输入 `docs/` 时列该目录子项，但没有独立的「下钻但先不引用」动作与面包屑                                                                                  |
| 空态与截断文案                                          | **未核对**           | 上游候选为空时不渲染任何行；知行明确给出「没有匹配」「工作区还没有文件」「没有项目工作区」「候选已截断」四句话。这是知行自己的文案，桌面版是否有等价提示未核对 |
| Windows 实包里的行为、真实模型读取                      | **未核对**           | 本轮证据只有 Linux 的 renderer 与 Node 层；没有在 Windows 安装包里点过                                                                                         |

## 测试

- `tests/file-mentions.test.mjs`（15 例，纯函数）：记号边界、引号、插入与不叠加、排序与并列、目录内查询、点路径、截断、三种空态。
- `tests/file-reference-list.test.mjs`（6 例，主机层）：递归相对路径、私密清单与 `isPrivateRelative` 一致、符号链接不跟随、条目上限、无工作区与空工作区。
- `tests/file-mention-ui.test.mjs`（真实 Electron renderer，7 个 PASS）：输入 `@` 出候选且只取一次索引、方向键与 Enter 插入、Esc 关闭与记号变化后重开、两种空态、切聊天关闭并重新取索引、手写 `@` 原样提交、IME 组合不抢键。

## 边界

- Linux renderer 与 Node 层通过，**不等于 Windows 实包验收**；本轮没有构建或安装包。
- 候选索引是合成工作区，**不等于真实项目目录**的性能与规模表现；条目上限之外的行为未测。
- 插入的是文本，模型是否真的去读、读到了什么，取决于真实模型与权限档位，本轮**未核对**。
- 排队的 `@` 仍是纯文本（排队账本不解析记号），编辑回输入框后若光标停在 `@…` 之后会重新给出候选，这是输入区行为而不是队列改写。
