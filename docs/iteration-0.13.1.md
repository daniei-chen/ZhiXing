# 知行 0.13.1 · 签名管道与长时间运行观察

这一版没有功能改动，补的是两件产品化基础：把「未签名」从硬编码变成可配置，以及第一次测量长时间运行的内存与句柄走势。

## 签名管道

此前 `electron-builder.yml` 里写死 `signExecutable: false`，等于任何情况下都不签名。现在移除该字段，恢复构建器默认行为：没有证书时日志输出 `no code signing certificate configured, signing is skipped`，构建照常成功；设置了 `CSC_LINK` 与 `CSC_KEY_PASSWORD` 后自动签名，不需要改代码。

同时补了 [签名说明](signing.md)：证书类型（OV / EV / 云签名）的取舍、验证命令、以及一个关键风险——`verifyUpdateCodeSignature` 默认为真，将来从「未签名」升到「已签名」时需要人工验证一次，避免发布者变化被更新器拒绝。

证书尚未申请，**没有任何一次构建在签名状态下验证过**，这是本版最明确的未完成项。

## 长时间运行

首次做空闲 soak：打包应用、独立临时档案、连续 29.8 分钟、54 次采样（每 30 秒一次，统计整棵进程树）。

| 指标 | 开始 | 结束 | 变化 |
| --- | --- | --- | --- |
| 进程数 | 4 | 4 | 0 |
| 工作集合计 | 393.1 MB | 394.1 MB | **+1.0 MB** |
| 句柄合计 | 2,313 | 2,390 | **+77** |
| CPU 累计 | 0.4 s | 0.7 s | 基本空闲 |

半小时内内存只涨 1 MB、句柄涨 77 个，进程数不变，CPU 几乎为零。空闲态没有可见泄漏。

边界要说清楚：这测的是**空闲**，没有会话、没有模型往返、没有文件监视高负载、没有长时间连续操作；句柄 +77 在 Chromium 的句柄池波动范围内，不能据此断言「永不泄漏」。真正的泄漏往往出现在反复创建会话或频繁刷新的路径上，那需要另一种带负载的测试。
