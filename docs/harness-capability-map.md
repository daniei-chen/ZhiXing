# 知行 · Harness 能力验收地图

本表区分实际运行的内核能力、界面接入和剩余工作。安装依赖、放置入口和读取目录均不等于端到端完成。用户要求的完整范围继续保留。

## 0.13.2 · 应用日志与诊断导出

新增 `electron/app-log.mjs`：事件级日志写入 `zhixing/logs/app.log`，1 MB 轮转保留两份，密钥类字段替换为 `[redacted]`，长串截断，不记聊天正文与文件内容。记录点：启动、自动更新状态、`uncaughtException`、`unhandledRejection`、`child-process-gone`、`render-process-gone`。注册 `uncaughtException` 后主进程不再因未捕获异常退出，属有意取舍。

设置 → 关于 →「导出诊断信息」生成 `diagnostics.json`（版本／平台／内存／数据量／更新与保存状态）加日志副本，端到端验证通过且不含凭据。

边界：没有远程上报，也没有 crashReporter 与 minidump；崩溃记录点未在真实崩溃下验证；日志明文存放。上版 2 项超时取消本轮未复现。

## 0.13.1 · 签名管道与长时间运行

签名从硬编码跳过改为构建器默认：无证书时 `no code signing certificate configured, signing is skipped`，设置 `CSC_LINK`／`CSC_KEY_PASSWORD` 后自动签名。证书未申请，**签名成功路径未验证**；`verifyUpdateCodeSignature` 默认为真，未签名升到已签名需人工验证一次。

首次空闲 soak：29.8 分钟、54 次采样，工作集 393.1→394.1 MB（+1.0 MB），句柄 2,313→2,390（+77），进程数恒为 4，CPU 近零。只覆盖空闲态，不含会话、模型往返与高负载文件监视。

目录包回归 323 项中 320 通过、0 失败、1 跳过、2 超时取消，取消项未定位。

## 0.13.0 · 应用内自动更新

接入 `electron-updater`：设置页检查、下载、重启安装，启动后 45 秒后台查一次但不自动下载，安装必须点击。`app-update.yml` 指向 GitHub `daniei-chen/ZhiXing`，`releaseType=prerelease`；安装包改名为 `ZhiXing-${version}-x64.exe`，使 `latest.yml` 的 `url` 与资产一致。`--dir` 构建不写 `app-update.yml`，已由 `scripts/write-update-config.mjs` 补齐。

本地 feed 实测：`checking → available(0.99.0) → downloading(100%) → downloaded`。

边界：只验证了检查、版本比较、下载与 sha512 校验，未从 GitHub 真实下载 338 MB 完整包，也未验证升级后新版本的启动与数据保留；安装包未签名，更新器不提供签名校验，SmartScreen 提示仍在。安装生命周期未在本版复跑。

## 0.12.12 · 工作区文件观察

打开文件面板时按项目目录建立监视（Windows 递归监视，其余降级单层），事件按 400 ms 合批上报，面板 300 ms 后重载当前目录；切换项目或关闭面板解除，重启后重建。

端到端实测：外部写入到达一条合批事件（`count:3`，路径正确），解除后事件停止；关闭期间写入的文件重启后出现在列表，监视重建成功，重启后的新写入再次被观察。**「跨启动文件观察」由未覆盖转为已接入。**

边界：只监视当前项目目录，只通知变化不做内容 diff，观察结果不自动进入模型上下文，脱敏与审批不变。递归监视在超大目录下的句柄开销未压测；面板只验证了事件与重新列目录，未在真实 UI 上逐个点击对照。

启动 10 次中位数 `initialise` 838 ms、窗口显示 953 ms、可交互 1,133 ms，与 `0.12.11` 差异在噪声内。

安装生命周期在本版安装包上复跑：首次安装、同版本覆盖、`0.12.11`→`0.12.12` 历史升级、卸载保留与重装保留全部通过，**历史版本升级不再是缺口**。已知上一版缺陷：`0.12.10` 在「外部写入后立即关闭窗口」时会被渲染进程旧状态覆盖，未修复。

## 0.12.11 · 首帧不等自动化与服务

自动化状态初始化与建窗并行，浏览器、终端与语音服务改为窗口显示后后台准备；`automation:`、`browser:`、`terminal:`、`speech:` 通道在 `handle` 中按前缀统一等待就绪，退出前仍等待自动化就绪再关闭。

Windows x64 空档案冷启动 10 次中位数：`initialise` 913 ms、窗口显示 1,044 ms、可交互 1,226 ms；`0.12.10` 的 5 次中位数为 1,017 / 1,131 / 1,281 ms。两者未做同环境交替对比，差异接近噪声下限，只作方向参考。

窗口刚出现时并行调用 `automation:list`、`browser:state`、`speech:status` 均返回正常结构，未因服务未就绪失败。尚存成本：延迟只改变顺序，模块导入与同步解析仍在主线程发生；并行导入此前已被实测否决。

## 0.12.10 · 启动诊断

启动阶段追踪（`ZHIXING_STARTUP_TRACE=1`）与测量工具（`scripts/probe-startup.mjs`）接入仓库。Windows x64 目录包空档案冷启动 5 次中位数 1,281 ms：`initialise` 占约八成，导入 173 ms、状态增至 632 ms、自动化增至 934 ms、服务增至 1,017 ms，窗口显示 1,131 ms，可交互 1,281 ms。

并行导入的尝试被实测否决（导入阶段 173 → 1,072 ms，整体慢约 240 ms）并回退，因此本轮不宣称启动提速。`0.12.9` 同机中位数 1,263 ms，差异在噪声内；Windows 单次启动波动可达数百毫秒，比较须取多次中位数。

## 0.12.9 · 安装包体积

打包树在复制锁定的生产依赖之后裁剪运行时不会加载的内容：TypeScript 源码（`.ts`、`.tsx`、`.mts`、`.cts`）、source map、`@types`、WebAssembly 版 OfficeKit 兜底与其它平台的 `node-pty` 预编译。win32-x64 的 OfficeKit 侧车、sharp、ripgrep、conpty、随包 Node 与许可证保留，实际移除 67,865 个文件、共 636 MB。

| 指标 | 0.12.8 | 0.12.9 |
| --- | --- | --- |
| 应用目录 | 1,454 MB | 818 MB |
| 安装器 | 562.8 MB | 322.8 MB |
| 生产包清单 | 1,170 | 1,154（16 个为裁剪包，审计单列） |

裁剪只作用于打包，不改变内核、审批、脱敏、沙箱、图片与存储行为；证据为裁剪后目录包的 322/323 回归与 5/5 桌面专项。安装目录不再包含依赖的 `.ts` 源码与 source map，既无法直接阅读依赖原始源码，也无法用 source map 还原堆栈行号。

## 0.12.8 · 会话工作目录

绑定项目后接入官方 `dsh-tool-working-directory`。模型可以查看当前目录，或切换到项目内已存在的子目录；相对路径的 `read`、`write`、`edit`、`apply_patch`、`glob`、`grep` 随该目录解析。切换目标先按当前目录还原，再经项目边界校验，项目外或符号链接逃逸被拒绝。目录变更写入 `working-directory/change` 事件并随会话保存，重开继续生效；计划模式只允许查看当前目录。

| 能力 | 本机合成回环 |
| --- | --- |
| 会话工作目录 | 在合成项目中切到 `section` 后，`read` 读到子目录内容而非根目录同名文件，`write` 落在子目录并触发一次审批，`grep` 只在子目录命中；`working_directory ../..` 被拒绝且不改变后续操作；重开会话后目录与搜索结果保持，历史事件记录实际目录 |
| 目录边界 | 切换目标必须是项目内已存在的真实目录；符号链接、项目外路径与含凭证的路径在切换前拒绝 |

工作目录只改变原生文件工具的相对路径解析，不改变沙箱、审批和发送范围；跨启动文件观察、常驻 Host 与真实云端仍未覆盖。

## 0.12.7 · 内核执行权限预设与 WebP/GIF 图片

输入区的执行权限选择在会话开始前固定为官方 `dsh-permission-presets` 的原生预设：未绑定项目为只读，请求批准为工作区写入，帮我批准为工作区写入加自动新建，完全访问为完全访问沙箱并保留逐次批准策略。`harness/permission-sync.mjs` 在主会话创建时设置预设并核对读回值，子会话不改写；内核诊断只在预设属于已知集合时返回它。

| 能力 | 本机合成回环 |
| --- | --- |
| 原生执行权限预设 | 同一原生会话依次以完全访问、请求批准、帮我批准运行，实际命令的沙箱模式、历史 `permission/preset` 事件与审批策略逐次一致；无项目诊断返回只读。同一会话降档后下一次命令即使用新的工作区沙箱 |
| WebP、单帧 GIF 图片 | 与 PNG/JPEG 共用主进程遮罩副本：本机 OCR 命中合成手机号并遮罩，出站副本重读不到原号码，副本统一为 PNG。动图、扩展名与内容不符、BMP 等不在支持范围的文件被拒绝，不截取首帧 |
| 项目图片路径 | 工作区内 WebP、单帧 GIF 经同一函数生成 PNG 副本；不支持的扩展名在读出文件前即拒绝 |

WebP/GIF 的透明通道按白底展开，动图和多画面文件整体拒绝。截图语义、OCR 漏检、手写与真实云端视觉质量仍未覆盖；Windows 实包证据待本轮验收补齐。

## 0.12.6 · 原生项目文件工具与会话导出

Windows 包随附固定版本 `0.2.2-rc.5`，接入 `read`、`write`、`edit`、`apply_patch`、`glob`、`grep` 与 `read_image`。官方工具注册、版本观察策略、文本执行和 ripgrep 由上游提供。知行在执行层限定项目范围，写入走原有审批，工具结果与持久呈现数据使用本机脱敏。工作区外、私密配置、非普通文件和项目外链接均受限。

| 能力 | 本机合成回环 |
| --- | --- |
| 原生读取、写入、编辑 | 实际收件包含脱敏占位符，本机文件保留正确字节。拒绝首次盲编辑、审批期间变更、未获许可、项目外路径和 junction。规划可调查文件，禁止写入 |
| 原生 `apply_patch` | 实际新增、更新、移动与删除。整批审批和原生预检，拒绝审批、错误锚点或项目外目标时无产物。最多八个互不重复的文件操作。提交阶段分步执行，先完成的步骤在后续失败时保留，执行面板显示未完成 |
| 原生 `glob`、`grep` | 启动随包 ripgrep，核对普通文件、敏感匹配行、文件夹和链接。结果超量时缩小查询范围。输出仅保留本机设定上限内的匹配，不生成溢出文件 |
| 原生 `read_image` | PNG 和 JPEG 经 Windows 本机 OCR 生成遮罩副本，独立网关核验实际 MIME 和字节。仅支持当前视觉模型的 Windows 项目手动交办，和 Office 渲染及手动图片共用四张限额 |
| 原生会话 Markdown | 「会话操作 → 导出聊天文件」中选择 Markdown 和单一发送模式。官方 formatter 读取加密会话已提交事件，保留用户消息、助手正文和工具活动；由当前规则和绑定接收范围的主机快照保存，不还原占位符，不请求模型 |

Windows x64 目录包通过 5 项桌面专项：拒绝原生 `write`、批准后部分完成的补丁、批准 Office 转换、重启后导出 Markdown 以及会话移动后旧审阅失效。核对了实际文件和本机模型收件，导出增加 0 次模型请求。其余表项按源码与包内合成回环记录。 [0.12.6 Windows 验收](windows-acceptance-0.12.6.md)

真实云端未验证。Windows OCR 遮罩范围限于本机识别到并命中规则的文字，全面 NER、手写、二维码、人脸和图表语义未覆盖。Markdown 只导出所选主会话的已提交记录，原生 ZIP、完整子会话和附件字节归档仍未接入。跨启动文件观察、原生 Auto reviewer、常驻 Host 和 OAuth 仍有缺口；完整权限预设由 0.12.7 补齐，工作目录切换由 0.12.8 补齐。

## 0.12.4 新增与修复

图片资料进入手动交办时，主进程按实际方向解码，移除元数据并在白底上展开透明像素。Windows OCR 读取同一图像，脱敏模式对规则命中的词框遮罩。非脱敏模式保留图像内容，依然去除元数据并检查 OCR 中的已知或规则识别凭证。工作区保存 OCR 文本及副本引用，图片数据由主进程管理。持久保存开启时，副本使用 Windows 用户加密。官方附件插件另有当前 Windows 用户的本地会话缓存，应与工作区加密副本分开评估。

DeepSeek 原生 Messages、兼容 Messages 和 Chat Completions 通过官方 SDK 接收编码图片块。网关按批准副本的 MIME、长度和 SHA-256 核验实际出站数据。会话重开时只有同一隐私策略下的批准图片可以重放。兼容供应商需在模型目录声明 `image` 模态。官方 DeepSeek Flash 能力来自固定模型目录和供应商文档。 [DeepSeek 视觉文档](https://api-docs.deepseek.com/guides/vision/)

`office_read_file` 对 PNG、JPEG、BMP、TIFF 走 Windows 本机 OCR，返回 `ocr-text` 覆盖范围和本机提示；识别出的文本经过现有任务脱敏映射后才进入模型工具结果。真实回环测试确认原始电话和图片字节都没有出现在模型线缆中。OCR 取消信号会传给 PowerShell 子进程。

`/plan` 和 `/plan off` 的命令结果现在按命令目标等待最终上下文投影；进入规划模式的检查不会把“命令已返回”误当成“状态已落盘”。

源码回归、同包视觉测试、Windows 页面和实际 NSIS 验收分别记录。资产、提交、检查计数和证据路径见 [0.12.4 Windows 验收页](windows-acceptance-0.12.4.md)。
