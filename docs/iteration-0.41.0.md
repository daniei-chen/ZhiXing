# 0.41.0 · 输入、流式正文与保存分离

## 目标与范围

本轮在 `d0a99ea` 的 Phase 0A / 0B 候选基础上进入 Phase 1。解决两个高频写入来源：每次编辑输入框都会改变整个工作空间状态，以及每段流式正文都会再次序列化、加密并覆写工作空间。同步增加全局与工作面板的 React 错误边界，并将新版本的 GitHub 发布改为可复现的流水线。

版本为 **0.41.0**，Electron 44.11.5、React 19.2.0、DeepSeek Harness 0.2.2-rc.5 不变。此前尚未发布的聊天结构、工具计数、侧栏归属、模型恢复、办公文件目录策略和工程门禁一并纳入；具体修复与审计纠正保留在 [Phase 0A](phase-0a-audit.md) 与 [Phase 0B](phase-0b-engineering.md)，不把它们重复算作本轮新增能力。

## 改动及理由

### 草稿按作用域更新

输入框与侧边聊天分别订阅自己的草稿键。连续输入不会调用 App 的工作空间 `setState`；只有草稿从空变为非空、从非空变为空等清单变化需要更新草稿提示。项目、聊天、资料和已完成消息因此不会因每个字符而重新计算。

草稿采用 400 ms 空闲延迟、2,000 ms 最长等待的写入调度。切换作用域会立即发起保存；交办、删除、手动保存和正常退出会等待保存完成。待处理附件仍绑定原草稿和文件 revision；发送只消费已经提交的 revision，失败不能覆盖用户后续输入或主动清空的新版草稿。

### 独立加密草稿覆盖层

原 `workspace.bin` 继续作为完整基线，新 `drafts.bin` 仅保存加密草稿映射。两者共用同一条串行提交队列与失败重试状态，不建立竞态的独立队列。完整保存把当前草稿一并写入基线并轮换内部 epoch；只有 epoch 相同的覆盖层可以用于恢复，空映射也表示明确清空。旧数据首次保存建立 epoch，保留既有键、归属、附件和 revision。

先写入新增视觉附件，再提交引用，最后回收不再引用的附件。完整保存后的覆盖层清理失败会显式报告，不能假报成功；旧 epoch 不能使已删除或已发送的草稿复活。草稿写入不调用自动化调度 tick。

`loadWorkspace` 等待同一队列完成；写入失败时拒绝以旧快照冒充最新状态。更新安装前也先请求 renderer 保存，再等待主机队列，失败时阻止本次安装动作。

### 流式正文局部渲染

运行中的正文按 `runId` 订阅，只更新正在输出的正文组件；主聊天和侧边聊天共用该机制。最终成功、失败、取消及进程收尾状态仍通过原终态逻辑写入工作空间，失败时保留已经确认的部分输出。没有改变内核压缩、模型路由、工具权限或脱敏规则。

### 界面错误边界

全局边界提供真实可用的重试和重新载入；工作面板边界隔离面板渲染与生命周期异常，保留兄弟聊天组件的状态。错误卡片与 renderer 诊断仅使用固定安全文案和代码，不展示或记录异常对象、堆栈中的用户内容。边界不清空工作空间，也不能替代主进程或异步任务的错误处理。

## 验证口径

源码聚焦测试覆盖保存队列合并、旧数据迁移、跨 epoch 恢复、容量与磁盘故障、关闭持久化、发送消费和失败恢复。App 源码回归直接计数连续编辑和流式事件造成的根组件渲染及整库保存；真实 React renderer 验证错误边界。Windows 实包另以生产预加载、实际加密文件、真实 Harness 与本地合成模型服务验证逐字输入、流式正文、刷新恢复和退出保存。

本文件是构建时的源码说明，**不能据此推断某个构建已经通过**。该次构建的源码提交、每层实际测试数、安装器 SHA256、依赖审计与启动测量，以发行资产 `acceptance-summary-0.41.0.json`、`windows-acceptance-0.41.0.md` 和 `packed-source-manifest.json` 为准。发布流水线只在所列门禁成功且全部资产校验一致后公开预发行版本。

## 本轮没验证什么

- 本机 `D:\应用\知行` 的安装、历史升级、卸载恢复、快捷方式和用户真实资料没有在此 Linux / 托管 Windows 环境中执行；没有清理用户的 87 GB 历史目录。
- 本轮没有用户真实云端 Key；本地合成模型测试不代表真实办公任务成功率。真实网络错误测试仅证明对应错误链路。
- 安装器仍未代码签名；NSIS 生成与文件校验不等于安装生命周期通过。自动更新前保存的代码修复不等于下载、安装和重启链路已重新验收。
- 完整工作空间仍有 12 MiB 上限；草稿覆盖层也有独立容量上限。没有完成 SQLite / Blob 迁移、便携备份、常驻 Host、Git 工作树快照或专业 Office 引擎。
- 未实现本阶段剩余的内联审批、Thinking 展示、富文本扩展、工作面板导航重构及消息队列；不把本轮基础拆分称作整个 Phase 1 完成。
- 原生进程被强制终止或断电不经过正常退出屏障；防抖窗口中的未提交输入不承诺零丢失。浏览器版本继续不向 localStorage 保存草稿正文和附件。
- 加密 epoch 是知行的持久化实现；与 Harness 已核对的是按键订阅和独立语义草稿，不宣称桌面磁盘格式完全相同。
