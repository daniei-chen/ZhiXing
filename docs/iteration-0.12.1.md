# 知行 0.12.1 · 隐私边界与可恢复交付

本轮从 `v0.12.0` / `f2882ad7444f78b15b65b71ff76e010b2c9807fb` 继续，内核仍固定 DeepSeek Harness `0.2.2-rc.5`。先完成凭证保护，再按用户提供的 2026-11-21 独立审计修复动态键、交付快照、退出隔离、自动化待保存结果及草稿生命周期，不把上游能力目录扩写为全部能力已经接入。具体修复合同及剩余项见 [审计修复说明](audit-remediation-0.12.1.md)，最终二进制的分层结果见 [Windows 验收记录](windows-acceptance-0.12.1.md)。

## 修复内容

1. **消除长度盲区**。已知凭证检测不再忽略短值；可用模型 Key 统一要求 8–1024 个无空格的可打印 ASCII 字符。保存、实际运行、目录请求和自动化预览均作主进程校验。旧配置的过短 Key 不删除、不静默继续使用，供应商页提示重新配置。8–11 字符的 Key 与更长 Key 使用同一独立检查。检测按原文与 NFKC/隐藏字符规范化视图比较，区分大小写；不能据此声称任意编码均可识别。
2. **原文模式仍阻断凭证**。`privacyPolicyForMode` 返回本次有效策略；非脱敏模式强制 SECRET 为 block，保留原始分类配置，使切回脱敏模式后仍能使用原先选择。调用链覆盖用户预览、HTTP 网关、带签名 thinking、办公与外部工具返回、网络工具参数、补充子任务内容、流式/最终回复。普通资料仍按原文模式发送；用户为其他类别配置的 block 规则继续生效。
3. **JSON 和还原边界**。网关递归检查解码后的字符串、属性名和标量，不只比较序列化后的 JSON。带引号或反斜杠的已知 Key 不因转义绕过。手动任务同时检查 prompt、bootstrapPrompt 和内核命令；内核预览在内存保留送检原文，实际运行不以已替换占位符代替原文作独立凭证比较。流式、部分和最终正文在本机还原后再次检查当前模型 Key。共享任务板同样逐值检查当前 Key。工作计划沿用执行预览的隐藏策略；交互提问的正文、说明和选项在还原后另查当前 Key。
4. **授权失效**。隐私引擎版本提高到 `0.12.1-local-v4`；旧引擎的自动化授权重启后暂停，需重新审阅。没有让调度任务暗中继承更宽的权限或改变已审阅的实际输入。
5. **设置与本机测试一致**。非脱敏模式的凭证处理显示为锁定“拦截”，说明“替换”只在脱敏模式生效。本地合成测试按当前模式运行，模式变动使旧结果失效，并明确本地测试不读取保存的 API Key；真实发送另有主进程检查。样例仍只在页面内存中，不保存、不发送。

## 独立审计收口

- **R01**：模型网关区分固定协议字段、动态字典及 schema 身份；敏感动态键安全拒绝，不通过改名破坏 properties/required/引用。真实 Harness 和官方 MCP 客户端也受 pre-execute 门禁保护；普通键的实际调用继续通行。
- **R02**：TXT/DOCX/XLSX 和分享使用主进程保存的审阅快照，继承当前自定义秘密和禁止规则。模式、策略、凭据、内容、范围或格式改变后重新审阅；文件和剪贴板使用主机正文，拒绝 renderer 注入 text。本人版保留普通个人信息，凭据及当前禁止规则仍拦截。
- **R03/R04**：业务完成、结果保存与进程退出分别记录。未确认退出的内核保留 handle、互斥和恢复文件，阻止同会话重跑或删除；自动化写盘失败保留正文并暂停，重试保存不重跑模型/工具，关闭仍失败则返回窗口。
- **R05/R07/R08**：删除按最新聊天归属级联草稿和解析副本，先持久化清理意图；成功后同步清理主机临时映射、旧预览及 renderer 缓存。失败/取消归档轨迹；失败原地恢复不覆盖新输入；资料去重追加，超限明确反馈。
- **R06**：独立 npm 从 11.17.0 更新到 11.21.3，核对实际 bundled 路径；保留无系统 Node/npm 的插件检查、安装脚本审阅、启用、更新和移除。目录清单、审计和 SBOM 与本轮构建指纹分开保存，不把 high/critical 为零写成零风险。

框架、存储体系、灰白界面、品牌和三个顶栏入口保持原方向。没有新增逐次脱敏确认，未选择新的内核功能替代本轮高优先验证。

Windows 故障验收后追加两项最小修复：空的收尾重试计划确实执行零次自动重试；加密上下文原子提交遇到 Windows 临时占用时，仅对同一份加密 temp 有界重试 rename。后者不重跑模型、工具或更新回调，持续失败保留旧文件并向上报错。完整回归中的原始 `EPERM` 日志保留，未确认具体占用者，也不把重试机制描述为所有文件锁问题均已根治。

## 接入程度和限制

这次没有替换 DeepSeek 内核、引入新的云端账号体系或把 Presidio、scrubadub、Gitleaks 引擎装入应用。独立已知值检查主要保护**当前所选模型 Key**；普通手动输入还会比较已配置的其他供应商 Key。没有为任意 MCP 凭据、所有历史 Key 或任意未知秘密建立全局秘密注册表。通用凭证仍依靠本机格式/字段/自定义前缀规则，不能识别全部无标记密码。

低于 8 字符的模型 Key 不再作为受支持连接使用，包括本机测试网关；需在服务侧换为较长的测试 Key。已知值的子串检查有意保守，Key 恰好是普通文本或号码时可能阻断正常内容，没有独立语料的误报率或召回率结论。

常驻 Host、跨轮 MCP/Jobs、MCP/供应商 OAuth、独立搜索、Responses/Gemini、完整原生文件/Office/Python 工具、增量加密存储、模型视觉、图像打码和全面 NER 仍待完成。工作区仍有 12 MiB 上限，历史仍全量加密写回。第三方插件自行联网与完全访问命令不是任意秘密外发的全局 DLP 沙箱。

Windows 默认真实 AppData 档案、交互/所有用户安装、跨账户迁移、真人麦克风、物理 DPI、完整无障碍与真实云端供应商矩阵的结论，只能以本版验收明确列出的证据为准；历史 0.12.0 证据不替代新包验收。

R09 无 owner 锁恢复、R10 完整目录分页、连续多份未发送草稿的可见入口、统一能力状态 manifest 尚未实施。独立资料库、磁盘原件及明确保留的自动化历史不是聊天草稿级联删除或物理安全擦除的范围。持续写盘失败后强杀/断电前未保存的结果不能保证恢复。

本轮定向组合两次出现 PTC 规划启动错误，规划请求未到达合成服务；五次独立 PTC 复验与后续组合回归通过，但根因尚未确定。原生任务失败现在保留经过执行预览策略隐藏的结构化诊断，测试另保留 SDK stderr；产品 IPC 继续只返回安全的通用错误。最终门禁通过不代表已修复此间歇问题或完成长期稳定性验收。PTC 继续默认关闭，不扩大其启用权限。
