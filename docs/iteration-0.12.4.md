# 知行 0.12.4 · 模型视觉与本机图片脱敏

本轮从 `v0.12.3` 继续，固定 DeepSeek Harness `0.2.2-rc.5`。新增手动交办的 PNG/JPEG 图片输入。项目、会话、既有顶栏入口以及用户选定的模型配置继续用于同一交办流程。

## 先复现的问题

首个候选在脱敏无命中时直接传递 JPEG 原文件字节，保留了合成 EXIF，还将内容类型报成 PNG。图片规则变化后原有副本缺少可信绑定，原生会话恢复也缺少可用的批准集合。原目录包测试入口遗漏了视觉用例。最终包重新构建，相关检查进入包内回归。

## 修复和行为

- `electron/visual-attachments.mjs` 核对扩展名与格式，按 EXIF 方向摆正，移除元数据，在白底上展开透明像素。Windows OCR 检查同一位图，返回行、词框及覆盖范围。脱敏模式遮住现有分类规则及自定义词的命中区域。零命中及纯图形仍使用重新编码后的副本。
- OCR 检查已配置的模型/MCP 凭证，并容忍识别结果中的空白拆分和 Unicode 规范化。命中阻断规则时拒绝准备副本。非脱敏模式依然检查可识别凭证，重新编码副本保留未遮罩的图像内容。
- 主进程按当前隐私规则、模式、自定义词和配置凭证批准图片。开启本地保存后，图片副本随草稿、资料或会话引用使用 Windows 用户加密持久化。前端持久状态含 OCR 文本、覆盖说明和副本引用。启用官方附件插件的原生会话另有本地内容缓存。
- DeepSeek、兼容 Messages 和 Chat Completions 使用官方 SDK 图片块。隐私网关校验图片实际 MIME、长度及 SHA-256。选择只支持文字的模型时在出站前拒绝并保留草稿。重开会话可重放同一策略批准的图片，设置改变后需新建会话并重新添加。
- 源文件上限为 10 MB、2000 万像素。发送副本上限为 1 MiB、200 万像素、最长边 2048 像素。同一会话最多添加 4 张图片，旧图可作为历史重放。`office_read_file`、BMP/TIFF、扫描及 Office 文档的既有 OCR 链继续提供所能提取的文字。

## 证据与依赖

源码和目录包中的 `tests/runtime-vision.test.mjs` 分别验证 Windows OCR 后的实际像素、EXIF 去除、凭证拒绝、官方 SDK 三种协议的出站字节以及重开会话后的批准约束。Windows 实包业务旅程单独记录导入、持久化、两次重启、供应商模型、推理档位和模型请求次数。NSIS 生命周期使用独立的同账户合成资料。 [Windows 验收记录](windows-acceptance-0.12.4.md)

图像处理将随官方附件插件已经分发的 `sharp@0.35.5` 声明为直接依赖，生产 lockfile 沿用同一个安装路径和版本。OCR 使用 Windows 自带引擎。生产路径 inventory、组件 SBOM 和 npm audit 范围见验收页。 [能力地图](harness-capability-map.md)

## 未覆盖与下一轮

本轮验证的是实际像素边界和本机合成服务的协议行为。真实 DeepSeek/兼容供应商账户、视觉回答质量及 OCR 召回率需要独立验证。手写、复杂版面、图表、二维码、人脸和 OCR 未识别区域可能包含尚未遮罩的信息。全面 NER、单独的截图自动上传、图片版 MCP 返回、远程 Files API 和定时任务图片输入仍未接入。

Windows OCR 读取进程的临时图像文件在调用收尾时删除。崩溃或断电后的残留、缓存安全擦除及 OCR 引擎覆盖率尚未专项验证。

下一轮优先用获授权的云端账户验证 DeepSeek Flash 对合成图表和扫描页的回答，再建立中文场景的漏检与误报语料。按测得的缺口评估本地补充检测和用户主动检查遮罩区域的入口，继续维持普通交办自动脱敏。
