## 隐私合同

- 引擎为 `0.12.1-local-v4`。旧引擎的自动化授权失效，需要重新审阅；不暗中放宽已批准的调度输入。
- 固定协议键不参与机械替换；动态数据键按当前策略检查。raw 允许普通个人信息原值，SECRET 和显式 block 仍拒绝。无法安全保持工具语义时拒绝出站，要求换安全字段或约束。
- 模型网关在实际上游收件前检查；MCP 和已接入扩展的 pre-execute 同样拒绝敏感动态参数。第三方插件自行建立的任意网络连接不构成已受全局 DLP 沙箱保护。
- 接收方交付版总是使用当前策略处理原文，不把旧 masked 内容当成当前规则的权威。本人版允许普通个人信息，但当前禁止规则、规则识别的 SECRET 与已配置凭据仍阻止交付。交付策略有意比 raw 模型发送更严格。
- 在交付与复制主机范围，秘密集合包含已配置的模型凭据、MCP 请求头和敏感命名环境变量值；Authorization 的 Bearer/Basic 裸令牌也独立检查。这不代表所有模型/MCP 出站已有全局秘密注册表。没有读取其他应用凭据，浏览器演示不读取保存的 Key。
- 快照文本由主进程保存，返回深副本；renderer 的 text 不能覆盖交付授权。成功使用后消耗快照；取消保存选择可重新确认；并发使用同一快照被拒绝；删除成功取消尚未完成的交付审阅。
- 识别仍是规则、校验位、字段、词表和已知值保护；没有安装完整 Presidio、scrubadub、Gitleaks 引擎、通用 NER 或视觉打码，也没有独立真实语料召回率/误报率结论。

## 失败与删除合同

业务执行结束不等于结果已保存，也不等于内核已退出。有效输出必须完成凭证、还原与未知占位符检查后才可标记 completed。关闭失败不会覆盖已经校验的正文；安全校验失败也不会借“模型已返回”标成成功。

自动化的保存失败正文保留在当前主进程内存，且正常退出被阻止。持续无法写盘时，强杀或断电前没有写成功的正文不能承诺恢复；重启对原 running 台账暂停并提示核对可能已发生的副作用，不自动重跑。

Windows 实测追加发现两个边界：显式空清理计划被未初始化计数误判，现保证零次自动重试，手动收尾继续使用原 handle；一次完整回归在加密上下文文件原子替换时遇到 `EPERM`。加密桥现仅对 Windows `EPERM/EACCES/EBUSY` 最多重试同一密文 temp 的 rename 八次（等待总和 1.1 秒），不重新序列化、不重写密文、不删除旧目标、不重跑业务。持续占用或其他错误仍抛出，原目标保留。测试核对重试次数、字节、旧文件、跨调用锁及回调次数；真实占用者没有定位，不能宣称已证明全部 Windows 文件锁根因。

删除先持久化目标移除及清理意图，再清理 native history/vault；失败持续可见，可只重试清理。删除针对聊天及所属草稿，不删除磁盘工作目录或独立资料库；删除定时任务仍遵循既有“已完成执行记录和聊天保留”合同。它不是物理安全擦除或所有独立记录的全局删除承诺。
