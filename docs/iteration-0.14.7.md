# 知行 0.14.7 · 把整个项目文件夹打成一个 ZIP

## 问题

到 0.14.6 为止，知行能导出的只有「一份内容」：聊天记录存成 Markdown、办公文件另存为 docx/xlsx/pptx。用户要把一个项目的全部文件交给同事或另一个工具时，只能自己打开资源管理器压缩——产品里没有这条路。

## 怎么改

工作面板「文件」页的工具栏多了一个「打包为 ZIP」按钮（`Archive` 图标，`aria-label="打包为 ZIP"`），把**当前所在文件夹**打成压缩包，走原生保存对话框。

主进程新增 `electron/zip-writer.mjs`，不引入任何新依赖：

- `buildZip`：用 `zlib.deflateRaw` + 自写本地文件头、中央目录与 EOCD。文件名置 UTF-8 标志位（bit 11），中文名在 Windows 资源管理器和 yauzl 里都能正确读回；内容压不小就退回 store。
- `normalizeEntryName`：归档内路径统一成 `/`，拒绝绝对路径、盘符、`..` 段与反斜杠穿越——解压时不会跑到目标目录外面。
- `collectDirectory`：不跟随符号链接，跳过私密清单，条目上限 2000、总字节上限 256 MB，超了给出明确错误而不是打出一个坏包。

私密清单直接复用 `workspace-files.mjs` 里已有的那份（`isPrivateRelative`）：`.env`、`*.pem`、`*.key`、`*.pfx`、`deepseek.credential`、`workspace.bin`、`automations.bin`、`vaults`、`node_modules`、`.git` 都不进包。

界面侧：成功时在文件列表上方给一条绿色提示「已打包 N 个文件 → 路径」；取消保存不写文件、也不提示成功。

## 结果

| 层 | 结果 |
| --- | --- |
| 源码 | `npm test` 389 个：388 通过、1 跳过、0 失败（新增 5 个：CRC32 标准向量、读回校验、不压缩模式、路径规范化与重名、目录收集与上限） |
| 实包 | `npm run test:zip` 4 项全过：入口可用（真实点击）→ 经原生对话框写盘 → yauzl 读回核对内容与排除项 → 取消不写盘 |
| 回归 | 打包源码 341、组件 14、站点 4、原生文件 5、错误文案 4+4、聊天失败 2+2、更新缓存 3、临时目录 2，全部通过 |

实包验收的细节：合成项目里有 `说明.md`、`src/data.txt`、`.env`、`id_rsa.pem`；打到 `.zip` 后读回只有前两个（`说明.md` 内容逐字节相等），`.env` 与 `.pem` 不在归档里；界面提示「已打包 2 个文件」。取消场景下归档文件不存在、提示也不出现。

## 边界

- 只能打包**当前文件夹**，没有多选、没有跨项目、没有增量与密码。空目录会被丢弃（ZIP 里不写目录项）。
- 上限 2000 个文件 / 256 MB，超过直接报错；没有做 ZIP64，所以不支持 4 GB 以上的包。
- 私密清单是路径名匹配，不是内容扫描：改名后的密钥（例如 `secret.txt`）不会被识别。
- 只在 Windows x64 实包验证；其他解压工具（7-Zip、macOS 归档工具）没有逐一核对，只用 yauzl 与 Windows 自带解压路径的能力假设做了读回。
- 大文件是整份读进内存再压缩，没有流式处理；256 MB 上限是这个设计的前提。
- 安装生命周期未在本轮复跑（安装器逻辑未改），`historical-upgrade` 仍是 `not_run`；安装器未签名；真实云端未覆盖。
