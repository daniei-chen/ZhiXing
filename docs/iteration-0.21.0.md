# 知行 0.21.0 · 详情里写明「这一轮是怎么发出去的」

## 问题

0.20.0 的「详情」能说清状态、耗时、工具、子任务、产出、占位符与错误码，却漏了最要紧的一件事：**这一轮到底是脱敏发出去的，还是原文发出去的**。

这两件事在界面上完全看不出来：同样的回答、同样的气泡，脱敏模式和明确开启的非脱敏模式长得一模一样。而这两个值其实早就记在消息上了——`privacyMode` 与 `protectCount`（本轮在本机替换了多少处敏感信息），只是从来没露过面。

## 怎么改

`src/run-summary.js` 两处小改：

- `runSummary` 多返回 `mode` 与 `protectedCount`：`privacyMode === 'raw'` 记「非脱敏模式」，其余有值的情况记「脱敏模式」，没有记录就留空。
- `summaryRows` 在状态后面插入「发送方式」行：有替换处数时写成「脱敏模式（本机替换 3 处敏感信息）」，没有就只写模式名；消息上没有 `privacyMode` 时**整行不生成**，不猜。

只读已记录的值：不推断、不回填、不把「看起来像脱敏」当成脱敏。单测新增 1 条（脱敏带处数、非脱敏、无记录三种情况），`tests/run-summary.test.mjs` 共 7 条。

## 结果

| 层 | 结果 |
| --- | --- |
| 源码 `npm test` | 431：430 通过、1 跳过、0 失败 |
| 组件 / 站点 | 14/14、4/4 |
| **实包（本地假服务，有占位符）** | `test:restore-gap` 5/5，新增断言：详情里「发送方式」以「脱敏模式」开头 |
| **实包（真实云端）** | `test:ui-status` 7/7，新增断言：真实一轮的「发送方式」是「脱敏模式」 |

## 边界

- 只显示**记录下来的**值：0.21.0 之前的老消息没有 `privacyMode`，详情里不会出现这一行——不回填、不猜。
- 「本机替换 N 处」是发送前本机替换的实体数（`protectCount`），**不等于**「多少处敏感信息被保护」，也不代表模型没看到原文的等价形式；附件未解析、图片未识别这些情况仍有各自的口径。
- 非脱敏模式下若凭证被拦截，这一轮根本发不出去，所以「非脱敏模式」只说明模式，不代表这一轮一定把原文送到了模型。
- 详情不含本次请求的脱敏内容（请求文本刻意不落盘）。
- 安装生命周期本版未重跑，最近一次完整证据仍是 0.19.0 的 53 步；`ENOTFOUND` 文案仍未端到端触发；安装器未签名；`visualAcceptance`、`crossWindowsUserDecryption` 仍 `outside_scope`；真实子任务归档仍未通过。
