# 知行 0.12.4 外部审计说明

请核对 `v0.12.4` 源码、完整 Windows x64 安装器，以及发行页公布的 SHA-256。`resources/app/build-provenance.json` 中的源码提交对应包内实际程序。标签可包含后续验收文档和测试脚本。用 source manifest、锁文件哈希和完整 diff 将报告归到具体构建。 [发行资产](https://github.com/daniei-chen/ZhiXing/releases/tag/v0.12.4) · [Windows 验收记录](windows-acceptance-0.12.4.md) · [能力地图](harness-capability-map.md)

## 复现重点

1. 用合成图片核对 PNG/JPEG 像素和 MIME。分别放入可 OCR 的合成手机号、自定义词、合成凭证和 EXIF 标记。检查遮罩、零命中仍去元数据、非脱敏模式凭证阻断，以及透明区域和 EXIF 旋转后的像素。保留原始输入、副本和出站数据的 SHA-256。
2. 在本机合成收件服务上检查 DeepSeek Messages、兼容 Messages 与 Chat Completions。记录所选模型和推理档位，发送一轮图片后关窗重启并追问。验证批准图像哈希相同、每轮只执行一次。改变隐私规则后验证旧图停止重放，当前输入仍可恢复。对纯文字模型验收发送前拒绝。
3. 对照安装器与包内构建清单。在隔离配置下复查加密副本和会话恢复。区分主进程工作区副本及 Harness 本地会话缓存。另行验证已安装程序的启动和安装保留分支。公开材料仅用合成样本和筛选后的验收记录。
4. 使用有明确授权的独立云端账户和合成图片，再测真实模型的视觉理解、各协议兼容性和拒绝行为。分开报告请求成功、回答正确率和 OCR 漏检。当前版本的公开证据以本机 Windows 合成账户为范围。

缺陷报告请附严重程度、构建 ID 或文件哈希、输入条件、真实出站次数、预期与实际行为。区分可复现缺陷、功能未接入和证据未覆盖。 [迭代与后续范围](iteration-0.12.4.md)
