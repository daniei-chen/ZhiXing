# 知行 0.13.6 · 更新后可追溯

两个日志字段，解决一个具体问题：更新装完之后，怎么知道它到底成了没有。

## 为什么加

上一版把自动更新的安装改成静默，但随即撞上一个尴尬：**一个版本没法用自己的安装包验证自己的更新修复**。跑在机器上的旧版本执行的是它内部打包的旧代码，所以 `0.13.4 → 0.13.5` 这场测试测的全是 `0.13.4` 的旧行为。

要确认修复，只能让 `0.13.5` 去检测一个更晚的版本。可就算装成了，光看版本号也说不清「这次启动是更新器拉起的，还是我自己点开」。日志里缺这一条。

## 改了什么

**`app.start` 多两个字段**：

```json
{"version":"0.13.6","previousVersion":"0.13.5","updated":true,...}
```

上次运行的版本记在 `<userData>/zhixing/last-version.txt`，每次启动读出、比较、再写回。`updated: true` 就意味着这次启动来自一次版本变更——更新器装完拉起的，或者用户装完新包手动打开的，至少能圈定范围。

**新增 `update.install` 记录**：

```json
{"version":"0.13.6","from":"0.13.5"}
```

此前只有 `update.state`（checking / available / downloaded），点下「重启并安装」之后就没有记录了，出问题无从判断到底是没触发、还是触发了没装成。

## 这两个字段也是验证手段

`0.13.6` 的静默安装只能用 `0.13.5` 去检测它来验证。届时日志会同时给出两条独立证据：

- 安装成功 → `last-version.txt` 从 `0.13.5` 变成 `0.13.6`，`app.start` 记下 `previousVersion: "0.13.5"`、`updated: true`；
- 自动重启 → 新版本进程自己起来，日志有这条 `app.start`；没有这条就说明装完没回来。

## 结果

源码 363/364（1 项条件跳过），目录包 322/323（0 失败、0 取消），Windows 桌面专项 5/5。

## 边界

`previousVersion` 只能说明「上次记录到这个版本」，不区分更新器安装和手动安装。要区分得靠 `update.install` 那条——两者时间对得上才构成完整链条。

`last-version.txt` 未加密，内容只是一个版本号，不含用户数据。
