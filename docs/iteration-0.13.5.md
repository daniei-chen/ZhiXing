# 知行 0.13.5 · 更新安装改静默

一个参数改动，修的是上一轮实测里断掉的那一环。

## 上一轮发现的断点

在 `0.13.4` 上第一次把自动更新整条链跑通：

```
0.13.3 连真实 GitHub → available 0.13.4
下载 308 秒（323 MB）
旧进程退出 ✓
安装器执行 ✓   exe 从 0.13.3.0 变成 0.13.4.0
应用自动重启 ✗   没有发生
```

查到的原因是产品调用的是 `quitAndInstall(false, true)`。第一个参数 `isSilent=false` 会让 NSIS 弹出安装向导；向导在「正在安装」之后停在完成页等人点，`isForceRunAfter=true` 因此没有机会生效——安装是成功了，但应用不会自己回来。

## 改了什么

```js
// 之前
autoUpdater.quitAndInstall(false, true)
// 现在
autoUpdater.quitAndInstall(true, true)
```

用户点「重启并安装」就已经是一次明确授权，再让他在安装向导里点一遍「完成」是多余步骤，而且这一步直接把「重启自动回来」变成了「装完就没反应」。

## 结果

源码 363/364（1 项条件跳过），目录包 322/323（0 失败、0 取消），Windows 桌面专项 5/5。

## 边界

**这个修复在发布时还没有经过实机验证**——验证它必须是「旧版本在跑 → 检测到新版本 → 装完自己回来」，而这条链路只有在 `0.13.5` 对外发布之后才能跑。发布后立即用打包的 `0.13.4` 做了一次，结果记在 [能力地图](harness-capability-map.md) 的当前状态总览里。

静默安装还意味着用户看不到安装进度。这是有意取舍：进度信息由应用内的「正在下载 / 准备安装」承担，装完由应用自己拉起。
