# 知行成熟化路线：按依赖与验收推进

更新：2026-11-27。历史源码起点为 `c2f7588` / `0.40.0`；已发布里程碑为 0.41.0 和 0.42.0，0.43.0 正处于普通审批、问答与运行接续的候选阶段。0.44.0 审计（[问题清单](audit-0.44.0.md)）已完成运行中排队与会话标题两项，其余项按下表顺序推进。实现与审计纠正见 [Phase 0A](phase-0a-audit.md)、[0.41.0](iteration-0.41.0.md)、[0.42.0](iteration-0.42.0.md) 和 [0.43.0 候选契约](approval-recovery-0.43.0.md)。

## 产品约束

沿用已确认的 Windows Electron 目标、DeepSeek Harness 真实内核、办公／政务两种模式、雪中墨竹品牌及中性灰白主题。底层协议、技能、压缩、会话与权限机制先核对上游，再决定适配。模型与强度入口保持用户已确定的交互；不能把审计中的不同布局建议自动当作已批准的新产品方向。

继续区分“已对标／部分／未做／未核对”。包存在、目录显示、合成模型执行、实包 UI 及真实用户场景分别记录，避免将一个层面的成功当成整个能力完成。

下面的周数是工作量排序参考，不是已经排定的日历或自动执行承诺。每阶段只有满足退出条件才升级状态。正式发布仍按现行清单执行；开发分支不靠升版本号表示进展。

- 清理前生成目标目录、大小、证据保留及排除清单；只操作确属本项目且可恢复的历史产物。未挂载 D 盘时不宣称释放空间。
- README、对标表、能力地图入口引用同一当前候选报告；历史验收保留原版本归属。

## 阶段 1：会话状态与交互解耦（参考第 2–3 周）

**已完成的两个增量：** 0.41.0 分离输入草稿、流式正文与完整工作空间保存，并加入全局及工作面板错误恢复；0.42.0 提供九个可见工作面板标签和右侧交付文字预览。两版均有独立正式 Windows 构建、实包专项和公开安装包，详见各版验收记录。不能将这两个增量等同于阶段 1 全部退出。

**0.44.0 审计增量：** 运行中排队（`src/message-queue.js`，Linux renderer 与 App 级合成 IPC 两层回归）与会话标题清洗（`src/session-title.js`，对齐 `dsh-session-title`）。审计结论中最重的三项仍未做：常驻内核（2A）、会话历史检索、插话发送；插话依赖常驻内核先在运行中接收新输入。

**0.43.0 候选：** 普通工具审批与必要问答接管所属聊天输入区；主机持有请求、取消信号和完整结果，已保存聊天的界面刷新接回原 run，保存结果后再确认交接。全局错误恢复明确停止交办；关闭聊天保存后的页面重载取消任务，确认进程清理后释放准确的临时结果。各项目前记“部分”，Windows 实包及发行结果待对应报告，不预填通过数。Action Cards、完整 App 拆分、专业富文本、思考显示、排队与纠偏仍未完成。

后续继续补齐输入、保存、流式更新的规模化性能基线：固定 1 / 6 / 11 MiB 档案、固定消息数与 10 秒输入脚本，分别测量渲染提交、IPC 次数、实际加密写入次数、主进程阻塞和草稿恢复。0.41.0 已分离输入、草稿持久化与流式正文状态，并在有界 Windows 夹具中验证；上述不同档案规模下的性能基线仍需补齐。

实施顺序：

1. 添加全局及工作面板错误边界，提供明确的恢复操作；错误不能导致覆盖最后可恢复的工作区快照。
2. 抽离草稿和流式消息状态，再按消息、工作台、导航、模态框拆分 `App.jsx`。优先使用明确的状态订阅与选择器；是否采用 Zustand 取决于迁移成本，而不是为了增加依赖。
3. 草稿独立防抖保存，并在发送、切换、窗口关闭时 flush。并发附件迟到、删除作用域、失败恢复和多草稿回切的既有契约必须保留。
4. 普通审批按上游 `allowed-once`／`rejected` 与原生取消落地；主机持有不可变请求，渲染器只能表达用户选择，不能回传新的路径或命令。真实委派子 Agent 的 `approvalPolicy: never` 保持不变，自动化不借用前台审批。Action Cards 的 `propose_action`、注册动作类型和技能约束单列后续工作；不能因有审批卡就宣布动作卡片完成。已有计划、资料、凭据版本和定时任务授权不可暗中继承更宽范围。
5. 代码高亮、公式、图表和安全图片按渲染风险分别接入；解释结果不会获得文件系统、网络或任意脚本权限。思考显示只呈现上游实际提供的可显示内容。
6. 工作面板标签、右侧预览、排队与中途纠偏按上游能力和用户既有要求逐项实现；未接入的操作不做可点假入口。

退出条件：输入不再驱动整库写入；同等夹具下有前后性能数据；草稿和消息故障恢复回归通过；审批由主机判定且取消无副作用；浏览器和 Windows 实包分别取得视觉与键盘操作证据。

## 阶段 2：运行时、存储和办公交付（参考第 4–6 周）

三个子项目可以分支并行，但各自先建立契约，再合入。不要在同一提交同时替换进程生命周期、存储格式和工具协议。

### 2A 常驻 Harness Host

先区分已经存在的上游能力与知行尚未完成的迁移。锁定的 `dsh-sdk-client/src/api.ts` 在同一个 `DeepSeekHarness` 对象内保存 `clientInstance` 并缓存 `start()` 的初始化 Promise，支持多次调用复用；知行当前 `RuntimeManager.run()` 每轮创建新对象并在最终清理关闭，尚未使用它实现跨轮常驻。无需另造 JSON-RPC 协议来填补一个 SDK 已具备的能力。

`dsh-cordis-host-runner/src/index.ts` 明确是同一 Cordis 内的动态插件定义、注册与运行生命周期服务，不是 OS 常驻进程管理器；不能将安装该包写成完成 Resident Host。`dsh-desktop-host` 的提供方接口和桌面组合也必须按实际调用核对，包清单或 SDK 能管理多会话都不证明知行已经接入。0.43.0 的结果交接只覆盖主进程存活期间的可靠传输，没有改变逐轮 Harness 进程生命周期。

迁移先明确常驻范围，再拆分长寿命宿主和逐次任务资源：供应商凭据、工作区、安全策略与隐私模式决定隔离；任务网关、脱敏保险库、桥接密钥、审批闭包、取消信号和环境配置不得因进程复用而串到下一轮。MCP 连接复用还须保留目标身份和配置变更失效规则。共享进程不等于共享任务映射或跨供应商历史。

必须分别记录业务完成、完整结果保存、会话释放和宿主进程退出。常驻后不能仍把“每轮进程退出”当作唯一完成条件，也不能直接删除现有 cleanup_pending 隔离与恢复资料契约。先定义取消、宿主崩溃、重连和保存重试的结果所有权，再调整释放逻辑；不以简单全局单例取代这些约束。

验收包括：首次启动和暖轮次分别测量；多会话并行互不串流；跨轮次 MCP 连接确实复用；服务中断、取消、窗口关闭和宿主崩溃下没有重复工具执行；长会话压力用例能重复运行。不要承诺“耗时归零”或“超时彻底根治”。

### 2B SQLite 与 Blob 存储

建议按 workspace、project、chat、message、trace、draft、document、automation 分离元数据与大对象，采用事务和增量写入。加密方案必须覆盖数据库、WAL、临时文件、搜索索引和备份；只加密正文而把全文索引留为明文不满足当前隐私目标。

迁移顺序为：冷备份 → 只读导入旧 `workspace.bin` → 数量／引用／内容校验 → 写入完成标记 → 启用新存储。模拟磁盘满、写入中断、坏附件、旧版本回退和重复迁移；旧文件在迁移核验前不得删除。

口令保护备份需包含密钥封装、认证完整性和导入失败回滚，避免继续依赖单机 DPAPI 才能迁移。搜索先明确权限和项目过滤，再接 Agent `session_query`；在搜索结果中保留来源定位和可删除性。

### 2C 专业 Office 引擎与可审查文件改动

保留已有原生文本工具、OfficeKit 转换／重算／渲染；分别定义创建新文件和修改现有文件，不让模型混淆“覆盖”和“自动另存”。

| 交付物   | 实现契约                                                         | 验收重点                                                                           |
| -------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| DOCX     | 结构化文档模型，标题、段落、列表、表格、页眉页脚；模板与正文分离 | 真实打开、页数和表格稳定、字体回退可控；公文模板另核正式标准，不宣称仅设字体即合规 |
| XLSX     | 有类型的单元格、公式、格式、多表及按需图表；模板编辑保留既有样式 | 重算后的值与独立计算核对；公式错误、隐藏区域、日期与精度有用例                     |
| PPTX     | 内容与布局结构分离，图片／图表来源可追溯                         | 渲染后逐页检查溢出、遮挡和字体；不能只验 ZIP 结构可打开                            |
| 原文修订 | 保留未修改内容、样式与批注；另存或显式覆盖授权                   | 修改范围精确，前后可对照，错误不破坏原件                                           |

工作区 checkpoint 应覆盖文件工具和终端写入，记录轮次前后状态；回滚只能恢复可归属于该轮的变更。用户或外部程序的并发编辑必须报告冲突，不能用整个工作区 `reset --hard` 覆盖。Git 未跟踪文件、二进制和项目外路径另设明确策略。

独立搜索和异构模型路由随后接入，保持工具网络授权、供应商切换隔离、上下文窗口和凭据版本检查；不以静默降级跨服务发送历史。

## 阶段 3：项目知识、协作与正式分发（参考第 7–10 周）

项目检索先做可解释的文档解析、分块、引用与增量更新，再比较全文与语义检索的实际收益。删除资料应同步删除索引及派生对象；项目和个人记忆须可查看、修改、禁用、导出及清除。

技能中心应基于真实 registry 和包来源；团队视图须能解释子任务状态、输出和失败。现有两协议 spawn 测试不是团队协作、fork、长期后台任务或异构模型全覆盖证明。

本地中文 NER 作为规则增强层，先建立真实脱敏评测语料和假名替换后的测试集，分别统计漏检、误杀及凭证阻断。普通实体白名单不能解除凭证阻断；隐私语义改变时提升引擎版本，使旧自动化授权重新审阅。

打包先检查外部 Node、原生模块、OfficeKit、ripgrep 等实际启动路径再决定 `asarUnpack`。将文件数、安装包体积、安装耗时和更新恢复分别测量，不把启用 asar 本身视为目标达成。代码签名、自动更新、旧档案迁移、卸载保留和崩溃诊断各有独立门禁。

## 真实任务评测与 v1.0 条件

从 30–50 个经用户授权的办公／政务任务建立固定任务集：会议纪要、跨表核对、带出处的汇报拟稿、模板修订、多步文件重排、工具失败恢复。使用合成或明确授权的数据；真实供应商凭据留在主机或受控 CI secret，不写报告。

每个任务记录完成标准、输入、预期交付、必要权限和人工可审查评分。分别统计任务完成率、数字准确性、格式质量、引用可追溯性、隐私泄漏、失败恢复和耗时。真实模型具有随机性，应记录模型、配置、样本数和失败实例，不能用一次成功概括稳定能力。

进入 v1.0 至少要求：日常资料规模不会触发不可恢复的保存上限；长会话和并发任务可恢复；Office 交付通过实际打开与视觉检查；所有可点主流程有真实能力；权限与隐私回归稳定；有对应版本的签名安装包、升级／卸载证据及可独立复验的发布资产。尚未覆盖的功能继续如实标注，不以总分替代验收。
