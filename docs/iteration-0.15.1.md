# 知行 0.15.1 · 工具调用直接列在消息下面

## 问题

上一版把状态行改成了「思考中／正在<工具>」，但用户仍然要打开右侧「执行」面板才知道这一轮到底调用了哪些工具、成没成功。DeepSeek Harness 的默认做法是把调用过程直接排在回答下面，知行应该对齐。

## 怎么改

- `src/run-status.js` 新增 `toolTimeline(trace, limit)`：把本轮的工具事件排成时间线，调用行与结果行都保留，带状态与耗时；只取最近 8 条。同时修正状态行：工具已经出结果（「网页搜索 · 完成」）时回落到「思考中」，不再把结果行当运行动作显示。
- `src/App.jsx`：回答下方渲染一个默认展开的 `<details class="tool-strip">`，标题是「N 次工具调用」，每行一条调用或结果；失败的条目描红；耗时不足 100 ms 的不显示数字（否则会出现「完成0.0s」）。
- 运行中读实时事件，结束后读消息里已保存的 `trace`，所以刷新后仍然看得到。

## 边界

- 这次是用**本地假服务 + 真实内核**触发工具（`todo_write`），不是真实云端；真实云端那一轮我试着让它调用 `glob`，模型明确回答「本次会话没有 glob 工具」——原因是文件类工具按工作区挂载，测试会话没有绑定项目工作区。**「在有工作区的项目会话里用真实云端跑一次文件工具」仍未验证。**
- 工具时间线只显示事件里已有的标签与耗时，不含参数与结果正文；要看完整参数仍在「执行」面板。
- 旧的 `liveToolCalls` 保留为兼容别名，实际实现已合并到 `toolTimeline`。
- 安装生命周期本轮未重跑；`visualAcceptance`、`crossWindowsUserDecryption` 仍 `outside_scope`；真实子任务归档仍未通过；安装器未签名。
