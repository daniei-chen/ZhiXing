# 知行 0.12.12 · 工作区文件观察

此前能力地图一直把「跨启动文件观察」列为未覆盖：文件面板只能手动刷新，应用关闭期间目录发生的变化也没有验证过。

## 改动

- **按项目目录监视。** 打开文件面板时对当前项目目录建立监视，Windows 用递归监视，平台不支持时降级为单层监视，失败只返回「未监视」而不会抛错。
- **合批上报。** 文件系统事件按 400 ms 合并成一次上报，携带变化次数与最多 20 条路径，避免编辑器连续写入刷爆通道。
- **面板自动刷新。** 收到本作用域的变化后，面板 300 ms 后重新加载当前目录；切换路径、切换项目或关闭面板都会解除监视。
- **应用重启后重建。** 监视随面板挂载重建；关闭期间发生的改动由重新读盘反映，不需要额外状态。

## 实测

同一台 Windows x64 机器、目录包，两个端到端脚本：

**运行期观察。** 建立监视返回 `watching: true`、作用域 `office-home:watch-project`。外部写入一个文件后，收到一条合批事件（`count: 3`，路径为 `created-by-outside.txt`）。解除监视后再写文件，不再收到任何事件。

**跨启动观察。** 关闭前目录只有 `before-restart.txt`；关闭期间写入 `written-while-closed.txt`；重启后同一项目列出两个文件，监视重新建立成功；重启后再写入 `written-after-restart.txt`，收到合批事件。两项都按预期成立。

## 启动

本轮主进程新增一个监视模块，但它与浏览器、终端、语音一起在窗口显示后才准备，不进首帧路径。10 次空档案冷启动中位数：`initialise` 838 ms、窗口显示 953 ms、可交互 1,133 ms。`0.12.11` 为 913 / 1,044 / 1,226 ms，差异仍在噪声范围内，**不作提速宣称**。

## 边界

监视只覆盖当前打开的项目目录，不监视项目外路径，也不监视磁盘上任意位置；不做文件内容级 diff，只通知「这里变了」。观察到的变化不会自动进入模型上下文——文件仍需手动加入交办，脱敏与审批链路不变。

面板只验证了接收事件与重新列目录，未在真实桌面 UI 上逐个点击刷新按钮对照；递归监视的句柄上限（项目目录过大时）未专项压测。

## 范围

审批、脱敏、沙箱、图片、存储与内核行为未变；源码回归、目录包回归与 Windows 桌面专项均重跑。安装生命周期本轮**未**在新包上复跑，安装证据仍是 `0.12.11` 那份。 [Windows 验收](windows-acceptance-0.12.12.md) · [能力地图](harness-capability-map.md)
