## 建议核对的实际调用链

1. **内核和协作**：从 `electron/runtime.mjs` 的 profile patch 跟到真实 Harness 的 Agent Teams、CAS revision、任务恢复与 PTC。核对默认配置、项目与完全访问门槛、规划模式、子工具审批及子任务停止。任务板上的文件范围只是协作声明，不能作为文件访问授权。
2. **Windows 执行边界**：检查 `harness/shell-policy.mjs`、`harness/office-tools.mjs` 和官方 `dsh-pwsh-sandbox` 的实际传参。分别复现 ask/auto/full 的项目内外写入、路径链接、秘密环境清除与沙箱失败。Windows ACL 写入约束不等于隔离全部读取、网络或用户已授予完全访问后的代码。
3. **模型请求与输出**：核对供应商、模型、推理档位严格选择，429/503 有界重试，主/子会话流归属，以及最终输出、部分草稿、工具输出和执行预览的当前 Key 硬阻断。区分本机合成收件测试与真实云端兼容性。
4. **脱敏绕过与误报**：检查 `src/privacy-core.js`、`src/privacy-recognizers.js`、隐私网关和映射生命周期。重点复现全角、零宽、方向控制字符、结构化字段别名、校验位、重叠词、自定义规则、伪造占位符、外部 MCP 参数和带签名 thinking 的失败关闭。使用独立合成语料统计漏检与误报，不从规则条数推断覆盖率。
5. **界面与真实状态**：从 React 设置、共享任务板、模型选择、执行面板跟到 preload/IPC 和主机状态；检查失效工具目录是否清除、本机测试是否落盘、停止后是否保留已有正文、保存失败是否持续可见，以及键盘/缩放/读屏可达性。
6. **安装包独立性与保留**：从源码目录外启动；移除外部 Node/npm PATH 后检查原生内核和插件安装。比较安装文件指纹、同账户加密资料、升级/覆盖/卸载/重装与快捷方式。第三方原生插件编译环境、签名、交互安装和跨 Windows 账号解密需要单独记录。

## 已知未完成范围

常驻 Harness Host、跨轮存活的 MCP/Jobs、MCP/供应商 OAuth、按需工具与重连、独立搜索凭据、Responses/Gemini 协议、增量加密存储、完整原生文件工具/Agent Office/离线 Python、模型视觉、原图打码和全面 NER 尚未完成。Presidio、scrubadub、Gitleaks 仅作设计资料参考，没有安装其引擎，也没有完整 Gitleaks 规则库或熵扫描。工作区仍有 12 MiB 上限，历史全量加密写回。

0.11.0 的历史安装记录只适用于其原始 SHA-256。请以 0.12.0 专项记录判断新包；没有列为通过的范围应继续复验。

## 审计输出格式

按严重程度列出发现，每条给出版本或文件 SHA-256、源码路径与行号、复现条件、实际行为、预期行为和影响。区分可复现缺陷、未实现能力与缺少验收证据。随后按依赖顺序提出修改模块、验证方法和 Windows 界面验收条件，列明需要真实供应商账户或人工现场验证的项目。

测试请使用合成资料、独立 user-data-dir 和专用项目目录。不要在报告、截图或服务收件记录中包含真实 Key、凭证或业务原件。
