# 知行 0.14.2 · 安装生命周期在 Electron 升级后复跑

这条待办是「验证」不是「修 bug」：最近一次完整安装生命周期证据是 `0.13.2`，而 Electron 在 `0.13.7` 升到了 `44.11.5`。之后没有任何一次运行能证明：在现在这个运行时上，安装、同版本覆盖、卸载保留、重装保留依然成立。

## 怎么跑的

`scripts/qa-install-lifecycle.ps1 -Mode Run` 要求四样输入，缺一不可：

| 输入 | 本轮怎么来 |
| --- | --- |
| 候选安装包 | `release/ZhiXing-0.14.1-x64.exe`（338,681,362 bytes，SHA-256 `5031d0d1…681c3`） |
| 合成 fixture 清单 | 复用旧轮创建的合成档案（一个项目、一个会话、一份草稿、一个 MCP），先用候选版真实读写一遍，再按读回结果写清单 |
| 主机冷字节备份 | 新增 `scripts/backup-host-bytes.ps1` 生成：两个 NSIS 默认数据目录 + 全部产品快捷方式，逐文件 SHA-256，抄完立刻回读比对 |
| 包内源码清单 | `0.14.1` 的 `packed-source-manifest.json`，用于在安装后核对「装进去的就是测过的源码」 |

前置状态：应用正常关闭（4 → 0 个进程）、卸载用户安装、机器上不存在任何产品快捷方式。运行耗时 21 分钟（`00:46:12` → `01:07:03`），44 个步骤，退出码 0。

| 覆盖项 | 结果 |
| --- | --- |
| 首次安装 | 通过（注册表、快捷方式、可执行文件与包版本都对上） |
| 同版本覆盖安装 | 通过 |
| 卸载默认保留数据 | 通过（卸载器不删 `%APPDATA%`，注册项清空） |
| 重装保留数据 | 通过 |
| 外部工作目录启动 | 通过（三次安装各一次，CDP 读真实 preload 接口后正常关闭） |
| 项目／会话／草稿哈希 | 通过 |
| 加密配置 | 通过（密文保留且应用可读） |
| 历史版本升级 | **未跑**（没有 BaselineInstaller，见边界） |
| 界面视觉验收、跨 Windows 账户解密 | 超出本脚本范围 |

安装目录 `.preview\i QA\知行-56cd`，全程未触碰用户真实档案；每个安装/卸载步骤都复核了真实档案的 112 个文件字节未变。

## 途中踩到的两个真实阻塞

这不是产品缺陷，是**测试顺序**缺陷，值得写下来：

1. **卸载用户安装会删掉两条快捷方式**。冷备份里记着 2 条，卸载后现场 0 条，脚本前置检查直接报 `Shortcut inventory differs from its byte backup`。正确顺序是「先备份、再卸载」，且卸载要保留快捷方式。
2. **恢复的快捷方式会让安装断言失败**。脚本的 `Assert-Installed` 要求「所有产品快捷方式都指向被测安装」，而指向 `D:\应用\知行` 的旧快捷方式此时是非法的，于是报 `Unexpected product shortcut target`。结论：测试期间机器上不能有产品快捷方式。本轮改为测试前按字节移出、备份清单记 0 条，测试结束后再按原字节还原并逐条核对 SHA-256。

两条都写进了 `AGENTS.md`，`scripts/backup-host-bytes.ps1` 也随本版入库，下一轮不必再摸一遍。

## 本版产品代码没有变化

`0.14.2` 与 `0.14.1` 的包内源码指纹完全相同（`248d3815…3533e`，90 个文件），安装器只差版本串与构建元数据。本版发布的是**证据与工具**：新增冷备份脚本、更新能力地图与三份文档。

## 边界

- **生命周期证据来自 `0.14.1` 安装包，不是 `0.14.2`**。两者应用负载同一份源码，但 `0.14.2` 的安装器没有重跑整套生命周期；只用它真实安装到用户环境并验证了启动（4 进程、版本 `0.14.2`、日志 `previousVersion 0.14.1`）。
- **历史版本升级未跑**：没有提供 `-BaselineInstaller`，所以「从旧版升级并迁移数据」本轮不计入。这一项自 `0.13.2` 起一直是 `not_run`。
- 视觉验收、跨 Windows 账户解密不在该脚本范围内，本轮也没有做。
- 冻结的测试环境只有一台机器、一个 Windows 账户；不同机器上的 NSIS 行为差异未覆盖。
