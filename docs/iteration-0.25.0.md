# 知行 0.25.0 · 执行轨迹可检索

## 解决什么问题

执行轨迹面板是查「这一轮到底做了什么」的地方。之前它只有筛选（交办 / 事件分类）和逐行展开，一次跑了十几个工具的长任务只能靠眼睛从上往下扫；桌面版 Trajectory 的工具栏里有「搜索轨迹」输入框和「展开／收起所有调用」这一组控件，知行缺了这两样。

本版补齐这两个入口，并向桌面版对齐文案：输入框 `aria-label="搜索轨迹"`、占位「搜索」，控件叫「收起所有事件」「展开所有事件」。

## 怎么改

- `src/trace-filter.js`（新，纯函数）：`normalizeQuery`／`matchesTrace`／`filterTrace`／`matchesLabel`／`traceSearchSummary`。匹配范围是事件的标签、状态、分类三项；子任务和后台作业按界面上显示的名字（「子任务 N」「作业 N」）参与匹配，这样搜索不会只命中主事件、却把折叠里的子调用漏掉。
- `src/ExecutionPanel.jsx`：新增 `input[aria-label="搜索轨迹"]`、两个按钮、匹配摘要「匹配 N / M 条」、空结果提示「没有匹配「X」的记录」；事件行的展开状态改为受控（`open={!collapsed.has(key)}`），这样才能做「全部收起／全部展开」。子任务与后台作业列表也按同一关键词过滤。
- `src/styles.css`：`.execution-search` 一行式工具条，窄面板下自动换行。

## 结果

- 源码层：`npm test` 452 项（451 通过 / 1 跳过 / 0 失败，新增 `trace-filter` 6 项）；`test:components` 14/14；`test:sites` 4/4。
- Windows 实包层：`npm run test:execution-search` 5/5——搜索框存在且占位为「搜索」；按「数字计算」过滤后只剩匹配行、摘要为「匹配 N / M 条」；输入不存在关键词时空列表并给出「没有匹配「不存在的工具名」的记录」；清空恢复全部；「收起所有事件」「展开所有事件」让所有行同步开合。`test:packed` 354（353 通过 / 1 跳过）、原生文件导出、启动采集（中位 798 / 902 / 1,074 ms）、依赖审计（1,178 / 1,162，0 high、0 critical）均通过。

## 边界

- **只对标到工具栏这一层**。桌面版 Trajectory 还有：按轮次分组的记录表（「第 N 轮」）、单条记录检查器（输入、输出、思考、token 用量、TTFT）、时间概览（缩放、拖选、吞吐）、按档折叠（轮次／调用／子调用分开控制）、`run_code` 的代码视图与语法高亮。这些**本版都没做**，对标表里仍记「部分」。
- 搜索只在当前选中的交办与当前事件分类内生效，不跨交办、不搜历史前缀（桌面版会按需加载更早的分页并一并搜索）。
- 匹配是大小写不敏感的子串，不做分词、不做高亮。
- 未在真实云端会话上执行本套验收；证据来自本地假 OpenAI 服务 + 打包后的真实内核。
