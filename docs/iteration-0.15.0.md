# 知行 0.15.0 · 发完消息先说「思考中」，拉取到的模型能直接选

## 你提的两件事

1. **发完消息显示的是内核自己的阶段名**（「内核启动中」），不像 DeepSeek Harness 那样先告诉你「思考中」。
2. **拉取到模型之后，在供应商页面里既看不到能选的入口，也没有「当前用哪个」的标记**——只能回到输入框的浮层里找。

## 怎么改

**状态行**：新增 `src/run-status.js`。运行中只显示两种文案：有工具在跑就显示「正在<工具名>」（例如「正在网页搜索」），否则显示「思考中」。内核的初始化阶段名不再出现在消息下方。5 个单测钉住：空事件、别的运行、只有推理事件、有工具事件、工具提示只取最近几条。

**模型选择**：供应商详情里的「已保存的模型」默认展开，每个模型一行：当前在用的那条带「当前」标记，其余每行一个「设为当前」。点它直接写工作区设置（`modelSelection`），消息里的「已保存的模型（47）」变成可操作列表。样式沿用既有的灰白列表，不新增强调色。

## 边界

- **没有做「删除单个模型」**：目前只能移除整个供应商，或改「手动添加模型 ID」后重新拉取。这一条留到下一轮。
- **没有展示模型的内置思考正文**：状态行能显示「思考中」和正在跑的工具名，但推理过程原文与工具调用的完整明细仍只在右侧「执行」面板里，消息下方没有内联卡片。要做到和 Harness 一样，需要内核把推理增量作为独立事件暴露出来。
- 思考强度仍只能在输入框底部那个合并入口里选，供应商页面没有加档位选择。
- 界面验收用的是真实云端（`zhihui.kaogong.art`、`deepseek-v4.1-flash`），只代表这一个供应商与模型；`auto` 是它目录里的一个模型，切过去只验证了设置落盘，没有真的让它回答。
- 安装生命周期本轮没有重跑；`visualAcceptance`、`crossWindowsUserDecryption` 仍 `outside_scope`；真实子任务归档仍未通过；安装器未签名。
